# Git Code Reviewer Introduction

Git Code Reviewer는 GitHub와 GitHub Enterprise Server의 Pull Request를 분석하고 변경 코드, 검토 보고서, 후속 질문을 한 화면에서 연결하는 코드 리뷰 웹서비스입니다. 개발자는 PR의 변경 의도와 위험을 확인하고, 검토 과정에서 확인한 판단을 다음 리뷰의 메모리로 남길 수 있습니다.

## 어떤 작업에 사용하는가

PR에 여러 파일이 함께 바뀌면 개별 diff만으로는 변경의 영향과 확인해야 할 항목을 파악하기 어렵습니다. Git Code Reviewer는 PR 전체 요약, 파일별 요약과 코드 위치에 연결된 상세 의견을 제공해 검토를 시작할 지점을 찾도록 돕습니다.

리뷰 중에는 Chat에서 여러 파일의 검토 결과를 종합해 질문할 수 있습니다. 반복해서 확인하는 저장소 규칙이나 GitHub PR 대화의 판단은 Memory에 저장해 이후 분석에 참고합니다.

## 검토 화면의 구성

| 메뉴                       | 확인하는 내용                                                         |
| -------------------------- | --------------------------------------------------------------------- |
| Pull requests              | 접근 가능한 PR, 분석 상태, 코드 품질 등급과 확인할 의견 수            |
| Code                       | 변경 diff, 코드 위치와 연결된 검토 의견                               |
| Summary                    | PR 전체 요약, 파일별 Overall Summary와 파일별 검토 상태               |
| Comments                   | finding을 단위 의견으로 표시한 문제·영향·권장 조치·근거               |
| Git graph · Impact · Tests | 분석 기준 commit, 영향 범위, 추가된 테스트 코드의 구조                |
| Chat                       | 보고서·메모리와 로컬 Git 기반 후속 분석, 사용자 확인·재개와 코드 근거 |
| Memory                     | 분석에 적용된 집단 메모리, 본인의 메모리 후보, GitHub PR 대화         |

Summary와 Comments는 구분되어 있습니다. 전체 변경을 이해할 때는 Summary를 읽고, 개별 판단을 검토할 때는 Comments와 Code를 함께 확인합니다. Chat은 화면 오른쪽에 있으며 Comments·Memory 등의 도구는 메인 영역 하단 탭에서 전환합니다.

## 처음 사용하는 순서

1. 관리자가 GitHub 연결과 repository를 등록하고 사용자에게 접근 권한을 부여합니다.
2. 관리자가 분석 Provider에 사용할 AI 모델을 설정합니다. 등록된 ChatGPT account 또는 OpenAI-compatible Provider를 사용할 수 있습니다.
3. 사용자는 Pull requests에서 PR을 열고 분석 진행 상태를 확인합니다.
4. Summary에서 전체 결과를 읽고 Comments와 diff에서 개별 의견의 근거를 확인합니다.
5. Chat에서 후속 질문을 하거나 Memory에서 재사용할 판단을 후보로 저장합니다.

Repository polling은 대상 저장소에 CI나 webhook을 추가하지 않고 PR 변경을 확인합니다. 분석에 필요한 Git revision은 Worker가 별도 작업공간에서 가져옵니다. 수동 새로고침으로 같은 commit을 새 설정과 메모리로 다시 분석할 수도 있습니다.

## 개인 경험과 저장소의 공통 판단

개인 메모리는 본인이 확인한 AI finding, Review Chat과 GitHub PR 대화에서 만들어집니다. 후보를 적용하면 본인의 후속 분석과 Chat에서 관련 항목을 참고할 수 있습니다. 모든 대화가 자동으로 승인된 규칙이 되는 것은 아니며 사용자가 후보를 검토합니다.

같은 repository에서 서로 다른 사용자 두 명 이상이 같은 검토 주제의 판단을 승인하면 집단 메모리 후보가 만들어집니다. 관리자는 기여 수와 충돌 수를 확인하고 Repository Memory에서 활성화합니다. GitHub 댓글의 작성자와 애플리케이션 사용자는 별도로 취급하며 기여자는 메모리를 승인한 애플리케이션 사용자로 계산합니다.

판단의 우선순위는 **현재 코드와 보고서의 근거 → 저장소 집단 메모리 → 개인 메모리**입니다. 과거 판단은 현재 코드에서 다시 확인할 참고 자료입니다. 공용 polling 분석은 집단 메모리를 사용하고 사용자가 요청한 개인 분석은 본인의 메모리도 참고합니다.

GitHub PR 일반 댓글, review 본문과 inline comment는 원문과 작성자, 원본 링크, 제공된 코드 위치를 함께 수집합니다. 사용자는 Memory의 PR 대화에서 후보 저장·무시·다시 표시를 선택할 수 있습니다. 이후 GitHub 댓글이 수정되어도 저장한 후보가 참조한 원문 버전은 보존됩니다.

## AI 리뷰 결과를 읽는 기준

실제 AI 분석에는 유효한 Provider와 계정 설정이 필요합니다. 화면에서 분석 중·완료·미완료·미수행·실패·데모 표시와 파일별 검토 상태를 확인하세요. 코드 품질 등급만으로 검토가 모두 완료됐다고 판단하지 않습니다.

Coverage는 확보하고 검토한 코드 범위를 나타냅니다. 테스트 통과율이나 AI 답변의 정확도는 아닙니다. Tests 탭은 추가된 테스트 코드에서 케이스와 기대 조건을 찾아 보여주며 테스트를 실행하지 않습니다.

Interactive Chat이 활성화된 환경에서는 snapshot의 base·merge-base·head를 로컬 Git에 확보하고 실제 파일과 Git 도구로 기존 구현·관련 테스트를 추가 조회합니다. AI가 요구사항을 질문하면 답변 후 분석을 이어 가며 중단하거나 재접속해 실행 상태를 확인할 수 있습니다. 조회한 코드 근거는 메인 탭에서 SHA·line과 함께 확인합니다. 코드 수정이나 테스트 실행은 허용하지 않으며 조회 실패·범위 제한을 안전하다는 결론으로 바꾸지 않습니다.

## 사용자와 관리자의 역할

일반 사용자는 허용된 repository를 검토하고 자신의 프로필, 개인 Prompt와 메모리를 관리합니다. Chat에는 관리자가 허용한 account·model·effort를 선택합니다.

관리자는 테넌트, 사용자, GitHub 연결, repository polling, 분석 Provider, tenant별 프롬프트와 분석 수준, 분석 Skills, ChatGPT accounts와 집단 메모리를 관리합니다. 공용 분석과 개인화 분석의 접근 범위를 구분하며 개인화 분석은 GitHub의 공용 리뷰 댓글로 게시하지 않습니다.
