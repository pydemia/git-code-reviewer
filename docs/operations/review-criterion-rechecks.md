# 리뷰 기준 재검토

중앙에서 발행할 기준의 출처와 유효 기간을 확인한다. 중앙 리뷰·지식·프롬프트를 로컬이 내려받고 로컬 모델로 실행하는 단방향 계약은 유지한다. 로컬 코드·결과·피드백·대화를 업로드하거나 중앙 모델에 실행을 맡기는 경로는 없다.

기준 목록과 상세 조회는 현재 DB snapshot에서 고정된 원문·metadata hash와 현재 출처를 대조한다. 출처 변경, 접근 불가, 출처 집합 hash 불일치, 재검토 날짜 도달, 현재 버전의 미철회 예외 만료를 구분한다. 목록의 필터는 최근 변경 기준 100개에 적용하며 전체 저장소의 재검토 대상을 열거하는 API는 아니다. 퇴역한 기준은 재검토 필터에서 제외한다.

출처가 달라지거나 사용할 수 없으면 기존 버전의 평가 기록 추가·평가 통과·책임자 승인·관찰 시작·활성화를 거부한다. 퇴역은 가능하다. 새 버전 작성은 상세와 선택 가능한 출처를 다시 조회하며 사용자가 최신 출처를 선택한다. 새 버전은 draft에서 시작하고 평가·승인을 다시 받아야 한다. 과거 판단과 평가 이력은 수정하지 않는다.

사용할 수 없는 출처는 상세 응답의 모든 버전에서 원문·label·코드/논의 metadata를 가린다. DB 원본 이력은 보존한다. unavailable은 삭제를 확정한 상태가 아니다. 저장소 접근 거부, 개인 범위 전환, 손상·미지원 출처 등으로 현재 사용할 수 없는 경우를 포함한다. 기준 본문과 사람이 작성한 판단·평가의 서술을 자동 삭제하지는 않는다.

코드 원문과 snapshot·파일·요청 metadata가 변경되거나 삭제되면 같은 transaction에서 policy 발행을 요청한다. 이전 bundle은 변경하지 않으며 다음 발행에서 유효하지 않은 기준을 제외한다. 새 발행을 로컬이 받기 전의 즉시 철회나 offline cache의 강제 무효화를 보장하지 않는다.

Migration 0049는 재검토 날짜, 예외 시작·만료 시각을 durable queue로 저장한다. 발행 worker는 최대 100건을 한 번에 처리하고 기존 주기 작업에서 약 1분마다 확인한다. worker 중단·혼잡 시 처리가 늦어질 수 있다. 처리 표시와 재발행 요청은 같은 transaction이며 동시 worker는 잠긴 일정을 건너뛴다. 구버전·퇴역 기준과 철회한 예외의 일정은 소비하되 발행을 요청하지 않는다.

재검토 날짜는 검토 알림 조건이다. 날짜만으로 기준을 퇴역하거나 제외하지 않는다. 예외 만료 후 새 bundle에는 해당 예외를 싣지 않고 기준은 유지한다. 이미 받은 bundle에서도 로컬의 기존 예외 기간 검사에 따라 기준을 다시 적용한다. 예외 연장은 새 요청과 독립 승인을 거쳐야 한다.

Provider의 명시적 삭제·접근 불가 관측, 대규모 재수집·재개, critical 기준의 즉시 철회와 offline 처리, 재발률 기반 재평가는 후속 범위다. P12-C04 전체 완료로 간주하지 않는다.
