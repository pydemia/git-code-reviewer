# 로컬 리뷰 실행 현황

Commit Defender의 명령 팔레트 또는 사이드바에서 `Local Review Activity`를 열고 최근 7·30·90일을 선택한다. 다시 실행하면 저장된 이력을 새로 읽는다. CLI는 `gcr history --stats --days 30`을 사용한다. 두 경로가 동일한 client-core 집계 함수를 사용한다.

중앙 리뷰와 프롬프트는 중앙에서 로컬로 내려받는다. 이 화면은 이미 로컬에 저장된 암호화 리뷰 이력만 읽으며 모델 실행·중앙 동기화·업로드를 요청하지 않는다. 기존 로컬 모델과 계정을 바꾸지 않는다. 중앙 서버의 관측 화면에는 이 결과를 보내지 않으므로 중앙에서 로컬 실행 수를 알 수 없다.

프로필·저장소·worktree와 선택한 중앙 연결을 기준으로 이력을 읽는다. 중앙 연결 이력은 저장 시의 audience를 검증하고 해당 연결의 유효한 로컬 인증 상태를 요구한다. 접근 불가 시 그 연결에서 생성한 로컬 fallback 이력만 표시하며 누락 사실을 알린다. standalone 조회는 중앙 namespace를 읽지 않는다. VS Code의 프로필·모드·workspace·중앙 연결 변경이나 Clear Findings는 기존 조회 화면을 닫고 진행 중인 읽기의 화면 재생성을 막는다.

기간은 완료 시각을 기준으로 양쪽 경계를 포함한다. 동일 run ID와 내용은 한 번만 세며 다른 내용의 동일 ID·다른 scope·비종료 기록은 오류다. 미래 완료 기록은 별도 제외 수로 남긴다. 보존 정책으로 지워지거나 저장되지 않은 실행 수는 추정하지 않는다. 사이드바의 최대 20건 목록이 아닌 해당 scope의 저장 이력 전체를 사용한다.

종료 상태와 원래 trigger를 그대로 집계한다. 시작 시각이 있는 기록의 duration만 합산하며 실제 모델 호출 수나 provider latency로 해석하지 않는다. 저장된 executor/model 목록에도 실행 전 중단된 기록이 포함될 수 있다. 목록은 실행 수 순 32개 그룹까지 표시하고 생략된 그룹 수를 알린다.

지적 severity는 모든 outcome을 포함하고 outcome별 수를 별도로 표시한다. 같은 지적이 여러 리뷰에 있으면 각 리뷰에서 센다. 중앙 snapshot 고정과 public policy 기준 선택은 입력 provenance이며 준수율·결함 해결·리뷰 품질을 증명하지 않는다. policy bundle 안의 Skill만 선택한 리뷰를 public 기준 선택으로 세지 않는다. 토큰·provider 호출 수·청구 비용은 미기록으로 유지한다.

이번 변경은 로컬 패키지·CLI·확장에 한정한다. 중앙 API·DB schema·Helm release의 변경은 필요하지 않다. 사용자 이력에 새 필드를 쓰거나 과거 기록을 보정하지 않는다.
