# C5 · U1/U2 리뷰 UI 게시와 PRISM-DEV 배포

2026-09-28. 사용자가 선택한 C5 팔레트와 U1/U2 혼합 구조를 실제 GCR 화면에 반영하고 기존 code diff를 보존했다. 브랜치는 `codex/windows-native-support`다.

## 제품 변경

- `theme.css`에 C5 canvas·surface·text·metadata·border 역할을 연결했다. 기존 청록 주색과 warning·danger 의미를 유지한다.
- 리뷰 상세에 PR·관측·이력 목적지 rail을 추가했다. 980px 이하에서는 기존 상단 탐색을 사용한다. 기존 파일·Outline·Impact, Split/Unified diff, 행·snapshot, 인라인 의견·행 이동, revision 선택, Chat·Summary·하단 도구와 크기 조절을 유지한다.
- 코멘트 옆 severity 색 띠와 그림자를 제거하고 중립 metadata 헤더와 본문을 연결했다. 수정 제안은 기존 별도 박스로 유지한다. 인라인 본문은 기존 안전한 Markdown renderer를 재사용하며 어두운 diff의 제목·링크·표·코드 글자색을 유지한다.
- 관측 화면은 필터·집계·내용 구획을 평평한 toolbar와 구분선으로 표현한다. 이력 선택 행의 옆 띠를 제거하고 원문·답글·버전·출처를 유지한다.

참고 구조는 승인된 [설계 기록](../design/review-ui-proposals-2026-09-27/hybrid-decision.md)의 Primer Timeline과 MUI Drawer/List다. 기존 React/CSS 컴포넌트를 재사용했고 dependency·API·인증·계정·모델·권한·분석 설정은 변경하지 않는다. 시안의 HTML·screenshot·`hybrid-build`는 별도 설계 자료이며 runtime build context에서 제외한다. 실제 제품 검증과 합성 fixture 근거는 구분한다.

## 빌드 재시도 기록

이전 app 이미지를 runtime base로 재사용한 빌드는 제품 컴파일 후 runtime COPY 단계에서 `mount options is too long`으로 실패했다. 누적된 base layer의 mount 경로가 원인으로 추정되어, 같은 고정 Node 베이스 `node:22-alpine@sha256:c610fcdfb1d5b4740dd70c284ed3cb16bb857e0f7166196e36a5501df7a3aa32`에서 runtime을 새로 조립한다. [Docker OverlayFS 문서](https://docs.docker.com/engine/storage/drivers/overlayfs-driver/)의 layer 제약을 참고했다. Docker 초기화·prune·기존 이미지·container·volume 삭제는 하지 않았다.

새 runtime 빌드 전 임시 Docker 설정의 registry tag probe 두 번은 실패 원인을 확정하지 못했다. 기본 Docker 설정에서는 `alpha.85: not found`를 확인했고 이어진 임시 설정 재검사도 통과했다. tag를 덮어쓰도록 검사 조건을 완화하지 않았다. 이 preflight 실패와 앞선 두 빌드를 완료한 게시로 계산하지 않는다.

## 운영 UI 확인

실제 로그인된 Chrome 세션과 기존 PR #1084의 Revision 4를 CUA로 확인했다. 합성 응답이나 시안 fixture로 운영 결과를 대체하지 않았다.

- 리뷰 의견 6건에 metadata 헤더와 동일한 좌·우 중립 border가 적용됐고 옆 severity 띠·그림자가 없다. 수정 제안 박스 6개와 실제 인라인 Markdown을 확인했다.
- 첫 의견의 `코드에서 보기`로 같은 snapshot의 line 62를 선택했다. Split/Unified에서 선택 행과 Markdown을 유지했다. 하단 높이를 키보드로 조절한 뒤 원래 값을 복원했다.
- 1280px 화면은 document 폭 1280px, 작업 영역 1220px이며 rail이 표시됐다. 390px 화면은 document 폭 390px, Unified diff·코멘트를 유지하고 rail·resizer를 숨겼다. 긴 코드 참조는 334px 내부 영역에서 가로 스크롤하며 문서 전체를 밀어내지 않는다.
- 관측의 실제 metrics와 5개 section은 반복 박스 없이 위 구분선으로 표현됐고 alert가 없다. rail의 관측 link로 이동했다.
- 이력에서 기존 PR #1084의 원문 card 20개, 답글 문맥 4개와 Markdown·GitHub 출처를 확인했다. 원문·변경 이력에서 저장된 본문 버전 1개와 원문 관측 1개가 조회됐다. 새 수집·원문 변경·지침 발행은 하지 않았다.
- 검증 후 revision·Split 모드·provider/model/effort 선택과 저장된 panel 크기 **420 / 480 / 391**을 배포 전과 대조해 복원했다. 반응형 viewport override도 해제했다.

Mac이 잠겨 있어 Chrome의 두 screenshot API가 `Page.captureScreenshot` timeout을 반환했고 native 화면 캡처도 사용할 수 없었다. 실제 DOM·UI 동작과 배포 자산은 확인했지만 운영 화면 screenshot은 미완료다. 설계 fixture screenshot을 새 운영 화면 캡처로 표시하지 않는다. Safari/Firefox·실제 screen reader 검증은 수행하지 않았다.

## 보존과 운영 중 추가된 기록

Secret·ConfigMap·PVC·HTTPRoute **27개**의 기존 UID·data/spec hash가 보존됐다. identity release가 같고 실제 Helm 값은 image tag/digest만 달라졌다. migration 60개 checksum과 DB TLS `verify-full`·TLSv1.3도 유지됐다.

조회한 17개 테이블에서 기존 행의 변경·삭제는 0건이다. account·credential·grant·repository·memory·knowledge·history collection 등 고정 항목은 전체 snapshot이 같았다. 작업 중 운영 서비스의 `analysis_runs` 1건·`reports` 1건·`model_request_ledger` 128건이 추가됐다. 처음에는 단순 전체 snapshot 동일성 검사가 실패했으나, 세 테이블의 **모든 기존 row hash가 그대로 남았고 추가된 row만 있음**을 확인했다. 실패를 무시하지 않고 고정 항목의 완전 동일성과 실행 기록의 기존 행 보존·추가 건수를 각각 검증했다.

본 작업의 수동 운영 분석 요청·실제 모델 시험·GitHub comment 게시 요청은 각각 **0회**다. 이 수치는 운영 서비스에서 계속 발생한 호출 기록까지 0이라는 뜻은 아니다. 기존 계정·모델·분석 한도·사용자 설정을 변경하지 않았으며 Docker 이미지·container·volume과 전역 CLI도 보존했다.
