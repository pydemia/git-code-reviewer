# 개인 설정 사이드 메뉴

기존 프로필 화면의 표시 이름·개인 Prompt·클라이언트 연결·비밀번호 폼을 세 메뉴로 나눴다. 상단 `내 프로필` 링크로 열고 `프로필 · 비밀번호 변경`, `Prompt`, `클라이언트 설정`을 선택한다. 계정 역할·인증 방식·tenant는 프로필 메뉴에서 확인한다.

`reference-led-frontend`와 agent-skills의 `product-ui-ux-design`, `web-publishing`, `frontend-development`를 적용했다. 실제 기존 ProfilePage 폼과 AdminPage의 사이드 메뉴, GuidePage의 URL 링크·선택 표시를 확인하고 구조·색상·컴포넌트를 재사용했다. 별도 디자인 라이브러리나 새로운 설정 API를 추가하지 않았다. 데스크톱은 왼쪽 메뉴와 오른쪽 폼, 좁은 화면은 간단한 계정 요약과 세 메뉴를 본문 위에 배치한다.

## 사용과 상태

- `/profile?tab=profile`: 표시 이름과 비밀번호, 역할·인증 방식·tenant.
- `/profile?tab=prompt`: 기존 개인 Prompt 폼.
- `/profile?tab=clients`: 기존 Commit Defender·GCR CLI 연결과 key 관리.
- 지정하지 않거나 잘못된 tab 값이면 프로필 메뉴를 표시한다. 메뉴 링크는 새 탭 열기와 직접 접근을 지원하고 일반 클릭은 현재 문서에서 전환한다. 뒤로·앞으로 가기와 새로고침에 선택 메뉴를 반영한다.
- 다른 메뉴로 전환할 때 폼을 제거하지 않고 `hidden`으로 감춰 작성 중인 값을 유지한다. 숨긴 내용은 화면과 접근성 tree 및 Tab 이동에서 제외된다. 메뉴 전환은 자동 저장이 아니며 새로고침·페이지 이탈에 미저장 값을 보존하는 기능은 추가하지 않았다.
- 기존 profile/password 권한 분기, 저장 API, password session 종료, key의 원문 표시·pagehide 정리·발급·폐기 및 만료 정책은 유지한다. API 초기 조회는 페이지당 한 번이며 메뉴 전환으로 반복하지 않는다.

## 검증

실제 frontend build를 합성 API에 연결해 IAB 브라우저에서 확인했다. 운영 데이터·계정을 fixture에 복사하지 않았으며 표시 이름·Prompt 저장은 합성 데이터에만 실행했다.

미저장 표시 이름, Prompt, key 이름·No expiration 선택이 메뉴 전환과 뒤로 가기 이후 유지됐다. Prompt와 표시 이름의 저장 응답 및 완료 메시지를 확인했다. 메뉴마다 하나의 내용 영역만 표시됐으며 클라이언트 메뉴에서 Tab 이동은 해당 화면의 설치 가이드 링크로, 프로필의 표시 이름에서 Tab 이동은 현재 비밀번호로 이어졌다. 숨은 Prompt·클라이언트 폼으로 이동하지 않았다. 직접 Prompt URL의 새로고침은 같은 메뉴와 저장된 지침을 표시했다.

320px에서도 가로 넘침이 없으며 420×760에서 가로 너비는 document·프로필 모두 420px이고 내부 스크롤로 Prompt 저장·비밀번호 변경 버튼이 화면 하단 665px에 표시됐다. header의 top은 0이다. 프로필·Prompt·클라이언트가 한 화면에 모두 쌓이던 구조를 제거했지만 각 메뉴의 긴 내용은 필요한 만큼 스크롤한다. PC와 좁은 viewport를 확인했으며 실제 모바일 기기·Safari·Firefox를 새로 시험한 결과는 아니다.

기존 header·개인 Prompt 11개 테스트, TypeScript를 포함한 web build, 변경 파일 ESLint·Prettier가 통과했다. 기존 Rollup annotation·bundle 크기 경고는 남아 있다. CSS 값을 복제하는 테스트를 추가하지 않고 실제 이동·값 유지·저장 응답·focus·좌표를 검사했다. 저장 후 비활성 버튼에 키를 보내려던 시험은 disabled 제약으로 거부돼 활성 textarea에서 Tab을 보내는 방식으로 바로잡았다. 제품 오류로 처리하지 않았다.
