## 실행 범위와 기대 결과

G02 PR #917·#915의 저장 이력과 지침 `9ee94837-fd43-46f6-ac03-30bdfb8d3575`, 원문 `4f94ce45-2f0e-42e5-98b4-6ed2c2fde3e1`을 재사용한다. 지침은 BlockUpdateRequest의 요청 값 검증을 Pydantic validator로 처리하되 DB·권한·저장 상태 검증은 제외한다. G02의 실제 원천 대조 결과를 재사용하고 이번 작업에서 추가 수집·신규 PR·외부 댓글 게시는 하지 않는다.

세 합성 저장소 사례는 실제 과거 지침의 적용 범위와 반증 조건을 검증하기 위한 입력이다. 모델 응답을 합성하지 않는다. 각 저장소에는 schema·service·API 호출부·저장소 계약·경계값 테스트·Pydantic 2 의존성 선언을 고정하며 모델은 이 문맥을 읽기만 한다.

| 사례 | 검토 대상과 변경 | 기대 결과 |
| --- | --- | --- |
| defect | schema.py: reference 유형에 reference_id가 필요하다는 model_validator를 같은 파일의 미호출 자유 함수로 옮김 | 요청 생성·preview·update에서 누락/null 값이 검증되지 않는 문제를 지적. 과거 지침의 요청 필드 간 검증 조건과 실제 호출 경로를 연결 |

모델은 기존 기본 Codex 계정의 `gpt-5.6-luna / high`다. 각 사례 1회, 총 3회, 회당 최대 240초가 초기 한도다. 기존 사용자 설정은 바꾸지 않고 별도 검증 Host에서 선택한다. 실패 시 원인부터 확인하며 추가 호출에는 수정·대상·추가 한도를 먼저 기록한다. 설치된 제품 worker를 사용하며 출력이나 모델 응답을 바꾸는 진단 wrapper는 사용하지 않는다.

실행 전 고정한 기대 결과와 실제 report를 대조한다. context entry·출처 hash는 자료 제공의 증거다. 모델이 작성한 rationale·summary의 출처 인용과 적용/반증 판단은 별도로 평가한다. 문맥에 자료가 있다는 이유만으로 실제 판단에 활용됐다고 단정하지 않는다. timeout·partial·형식 오류·기대와 다른 판단은 통과로 바꾸지 않는다.
