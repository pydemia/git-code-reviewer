## 실행 범위와 기대 결과

세 합성 저장소 사례는 실제 과거 지침의 적용 범위와 반증 조건을 검증하기 위한 입력이다. 모델 응답을 합성하지 않는다. 각 저장소에는 schema·service·API 호출부·저장소 계약·경계값 테스트·Pydantic 2 의존성 선언을 고정하며 모델은 이 문맥을 읽기만 한다.

## 초기 실제 실행과 보완 판단

- defect: 설치된 2.11.1 worker에서 Luna/high 1회, 119,463ms, completed. 미호출 자유 함수로 옮긴 교차 필드 검증의 누락을 P2로 지적했다. 현재 caller·Pydantic 계약·반증을 설명했지만 모델 본문에 과거 출처 인용은 없었다. 자동 context/provenance 기록은 자료 제공 증거로만 인정하며 A05의 역사 자료 활용 증거는 아직 부족하다.
- fixed: 같은 설치에서 1회, 60,704ms, cancelled. manifest의 offlineValidUntil은 2026-09-16T15:29:02.357Z이며 온라인 발행/5분 만료 경계는 2026-09-15T15:29:02.357Z/15:34:02.357Z다. 종료 15:34:02.542Z는 이 경계와 일치한다. 240초 모델 한도 이전의 중앙 문맥 만료이며 정상 결과로 집계하지 않는다. 신규 Host라도 서버가 재사용하는 manifest의 잔여 수명이 짧을 수 있다.
- unrelated: 초기 한도 내 세 번째 호출을 진행한다. 다음 재검증은 시작 전 manifest 잔여 수명이 모델 한도와 준비 여유를 충족하는지 확인하고 부족하면 만료 후 정상 재동기화한다. 유효기간 자체나 철회 검사는 완화하지 않는다.

무관 사례도 84,394ms에 completed, findings 0으로 끝났다. archived DB 상태 검증을 schema로 옮기라는 오지적은 없었지만 모델 summary에는 과거 출처/제외 판단이 없었다. 실제 두 완료 사례는 현재 코드 판단이 기대와 맞았고 A05의 역사 자료 활용 설명이 부족했다.

G04에 필요한 최소 제품 보완은 sourceHistory가 있는 경우 기존 top-level summary에 출처 ID·원문 URL과 현재 코드에 대한 적용/충족/제외/미사용 판단을 남기라는 지침이다. 결과 schema나 실행 기능은 추가하지 않으며 미사용도 그대로 밝히게 한다. finding이 없는 결과에도 제외 근거를 표시하되 지적이나 역사 자료의 영향을 만들어내도록 요구하지 않는다. 이를 공통 client alpha.42·내부 서비스 alpha.37·CD 2.11.2로 전달한다. runtime 변경은 없으므로 Helm 재배포하지 않는다.

보완 후 추가 실제 호출 한도는 세 사례 각 1회, 총 3회, 각각 최대 240초다. 전체 누적 한도는 초기 3회와 합쳐 6회다. 같은 fixture·기본 계정 Luna/high를 사용하고 변경된 프롬프트의 출처/적용 설명과 fixed의 정상 완료를 재검증한다. 호출 전에 온라인 manifest의 남은 수명이 270초 이상인지 확인하고 부족하면 기존 만료 후 정상 동기화를 기다린다. 대기는 모델 호출로 계산하지 않으며 준비 중 충분한 수명이 사라지면 모델 실행 전에 중단한다.
