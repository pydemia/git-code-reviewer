## 사용 절차

1. 기존 사용자 계정·로컬 provider/model 설정을 유지하고 `Commit Defender: Central Review Connection`에서 해당 profile/worktree의 기존 reader 연결을 선택한다. 중앙 연결은 모델 실행 계정을 바꾸지 않는다.
2. `Central Review Connection → Browse PR review history`에서 PR #917 또는 #915를 선택해 원문·답글·본문 버전·출처 링크를 확인한다. 활성 지침의 적용 범위와 반증 조건을 함께 읽는다. 새 원문 수집이나 원문 승인 단계는 필요하지 않다.
3. CD에서 필요한 변경을 stage하고 `Commit Defender: Analyze Staged Files`를 실행한다. Skill·활성 지침과 관련 원문은 로컬에서 선택되며 실행의 자료 버전과 소스 snapshot은 고정된다. 결과에서 원문 URL·출처 ID·revision/hash와 모델의 적용/제외 설명을 확인한다.
4. 결과가 cancelled·timeout·partial·failed이면 완료된 리뷰로 사용하지 않는다. 온라인 manifest는 5분 경계에서 종료될 수 있으므로 정상 재동기화한 뒤 다시 실행한다. 기존 signed offline 모드는 허용된 수명과 권한 내에서만 사용하며 이미 확인된 철회나 만료를 우회하지 않는다.
5. 새 설치가 기존 사용자 창에 아직 적용되지 않았다면 편한 시점에 사용자가 창을 다시 열거나 재로드한다. 이번 작업은 재로드를 강제하지 않는다. Marketplace 게시는 별도로 진행한다.

2.11.2의 첫 보완 실행은 107,932ms에 completed다. 모델이 실제 원문 ID/URL을 인용하고 현재 코드에는 validator 지침이 반영되지 않았으며 과거 “수정 완료” 답변은 증거로 인정하지 않는다고 설명했다. 누락/null 호출 경로의 P2 1건도 현재 source/base에 근거했다.

화면 대조에서 기존 SummaryView가 per-file summary가 있으면 top-level summary를 숨기는 문제를 확인했다. 과거 출처 context가 있는 결과에 한해 전체 요약을 파일별 요약 앞에 함께 표시한다. 기존 safe Markdown 경로와 출처/버전 표시는 유지한다. 이 CD 표시 수정은 2.11.3으로 전달하며 client alpha.42·service alpha.37·모델 worker bytes는 동일하다. 실제 모델 재검증은 이미 설치한 2.11.2의 동일 worker로 이어서 수행하고 최종 2.11.3 Host에서는 저장된 실제 결과의 표시를 모델 추가 호출 없이 확인한다.

## 남은 제한

실제 모델 검증은 기본 Codex 계정의 Luna/high와 고정한 세 변경 사례에 한정한다. 다른 provider의 근거는 기존 계약·회귀 검사이며 실제 호출로 확대하지 않았다. 모델의 명시적 설명은 현재 소스에 비추어 판단한 활용 근거로 다루며 내부 추론의 인과관계를 증명한다고 주장하지 않는다.

원천 이력 대조는 G02의 지정 PR과 당시 수집된 범위를 재사용했다. 수집 이전의 수정·삭제 내용을 복원하지 않았다. 기존 G01 복구 분석의 공용 기준 연결 partial 제한도 유지한다. 검증 fixture의 경계값 테스트는 모델이 읽은 고정 문맥이며 실제 pytest 실행 증거로 집계하지 않는다.

온라인 manifest의 5분 유효기간은 그대로다. 새 Host라도 기존 manifest를 받을 수 있으므로 이번 검증 harness는 충분한 잔여 수명을 기다린 뒤 모델을 호출했다. 이 대기 처리를 제품 자동화로 추가하지 않았다.
