## G01-C01 — worker 장애 처리

수정 commit: `dcb9991`. 기존 worker의 이전 컨테이너 로그에서 pg idle pool의 처리되지 않은 `error` 이벤트와 `Connection terminated unexpectedly` 종료를 확인했다. PostgreSQL 재시작 직후에는 worker가 실행 상태이나 NotReady였으며 실행권이 만료된 분석을 회수하지 않았다. 현재 컨테이너의 초기 오류 로그는 남아 있지 않아 그 오류 문자열까지 확정하지 않는다.

코드에서는 health listener를 먼저 연 뒤 실행하는 초기 recovery 또는 후속 queue 조회가 실패하면 `runWorker`가 reject해도 listener가 열린 채 남았다. 상위 catch의 `process.exitCode=1`만으로는 프로세스가 끝나지 않는다. 이 경로를 실제 Fastify listener로 재현했다. 수정 전 listener 관련 2건 실패·정상 종료 1건 통과, 수정 후 3건 통과다.

- pg pool의 idle error에 고정된 비민감 오류 코드만 기록한다. 끊어진 idle client는 pg가 제거하고 다음 query는 새 연결을 얻는다. [pg Pool 문서](https://node-postgres.com/apis/pool)의 동작을 따른다.
- worker loop가 실패하면 health listener를 닫고 진행 중 작업을 drain한 뒤 pool을 종료한다. liveness/readiness 기준을 완화하지 않는다.
- 실제 로컬 PostgreSQL 연결 종료 후 재연결과 실제 startup query 실패 후 listener 정리를 검증했다. 기존 실행권 회수·checkpoint·중복 작업 방지 테스트도 통과했다. PostgreSQL의 과거 OOM 자체를 해결한 것으로 보고하지 않는다.

## G01-C02 — 선택 자료 실패와 기본 리뷰 분리

수정 commit: `d8405efdd4581c08096ab3344c1fbb00016832dc`. 새 분석은 기본 Skill을 활성 Skill 설정에서 고정한다. 선택적인 공용 발행본·원문 확인 실패가 기본 모델을 비활성화하지 않는다. 누락·손상·다른 repository/tenant 범위의 자료는 모델 입력에서 제외하고 공용 자료 상태를 `unavailable`로 기록한다. 기본 리뷰는 자체 실행 결과에 따라 완료·실패·미완료로 남는다.

검증은 실제 로컬 PostgreSQL에 저장한 작업을 worker 함수로 실행하고 합성 모델 요청·보고서를 대조했다. 정상 공용 기준 적용, 원문 획득 실패, 발행본 누락, 해시 손상, 다른 저장소 범위를 확인했다. 고정된 context의 유효기간 검사와 기존 source/model 실패 처리는 유지한다. 이미 시작한 분석의 immutable pin과 이후 발행본 변경은 구분하며, G02의 철회·이력 기능을 새로 개발하지 않았다.

최종 회귀 검사 6개 파일 49건 통과. native PostgreSQL 18.3 테스트 환경은 종료·삭제했다. 실제 shared-knowledge API 응답과 1360px·420px 브라우저 화면 검사를 포함한다. 모델은 합성 응답이며 실제 외부 PR 게시 검증으로 계산하지 않는다. 중간에 fixture mode를 잘못 지정한 추가 검사 1건이 실패했고 disabled GitHub mode로 수정한 뒤 전체 49건이 통과했다.

전체 package/runtime/web 빌드, 변경 TypeScript ESLint, diff 공백 검사가 통과했다. 새 worktree에서 `pnpm pack:cli --verify`로 client 3종과 CLI tarball을 생성하고 임시 consumer import/명령 검사를 수행했다. runner 파일·연결이 source·dist·tarball에 없음을 확인했다. 새 패키지를 사용자 환경에 설치하거나 공개 발행하지 않았다.

## G01-D01 — 운영 전달

PRISM-DEV의 기존 값·Secret·HTTPRoute·PVC와 주요 데이터 행의 배포 전 fingerprint를 기록했다. source `d8405ef`의 `git archive`로 새 rootless BuildKit에서 이미지를 빌드한다. 원래 checkout의 dist나 Docker image store를 사용하지 않는다. 배포 release는 runtime `0.8.0-alpha.61`, chart `0.10.57`이며 migration 52개와 TLS `verify-full`을 유지한다.

Helm revision `71`, image `sha256:4e31905a1e9e2830231c7fa2142234c3304bfbed126fa29bdc278023736240fe`. OCI chart digest는 `sha256:6f57884d9f9088a3173caac921dc2ba5fdf4b1f4958179c32c6f0e749fd17e7c`다. 버전 pin commit `2732c3c`를 push했다. 배포 전 서버 dry-run에서 runtime 이미지와 release 표기 외 manifest·values가 같음을 확인했다.

server와 worker가 Ready이며 이미지의 compiled module·웹 asset hash가 실행 중인 container 및 HTTPS 응답과 일치한다. Helm 연결 테스트는 `Succeeded`, Keycloak 2개 pod도 Ready다. 기존 52개 migration checksum, 비이미지 Helm values, Secret·Route·PVC와 기존 사용자·권한·계정·분석·보고서·메모리 행을 보존했다. AUTH_MODE와 DB TLS는 `local` / `verify-full`을 유지한다. [배포 대조](evidence/G01-deployment.json)를 따른다.

복구한 작업은 `f90dfba0-298d-430a-89ea-4e6e6aebaaea`, 분석은 `3fc73277-6934-4cf8-8275-241ee842b6a4`다. 11:35 KST에 만료됐던 실행권을 새 worker가 회수했다. 첫 시도를 `WORKER_LEASE_EXPIRED` / `interrupted`로 닫고 두 번째 시도를 완료했으며 recovery count는 1이다. 함께 대기하던 snapshot 작업 3건도 각각 첫 시도로 완료했다. 16:49 KST 확인 시 만료된 running 작업은 0건이다.

분석은 16:48:43 KST에 `partial`, progress 100으로 종료됐다. 변경 파일 4개를 모두 검토하고 보고서 `1b711386-1621-4194-b1fd-4bedf0e4316f` 1건을 저장했다. 기존 중앙 provider·모델 설정을 사용했으며 완료된 모델 요청은 17건, checkpoint는 17개다. 이전 `sent` 요청 1건은 기존 admission 로직이 `interrupted`로 정리했다. 중단 전 완료 checkpoint는 없었다. 이미 완료된 요청을 실제로 재사용한 사례로 과장하지 않으며 재사용·중복 방지는 별도 회귀 검사로 검증했다.

`partial` 사유는 “일부 지적의 공용 기준 연결을 확인하지 못했습니다”다. 보고서에는 지적 1건의 기준 연결이 `unavailable`로 남는다. 모델 리뷰가 실행되지 않은 상태와 구분한다. 이 결과를 공용 기준 검증 완료로 바꾸거나 같은 분석을 임의 재실행하지 않았다. 이번 goal은 작업 복구·정합한 종료까지 포함하며 기존 기준 연결 품질 개선으로 확장하지 않는다. [복구 전](evidence/G01-recovery-before.json), [복구 후](evidence/G01-recovery-after.json), [보고서 상태](evidence/G01-recovered-report.json)를 확인할 수 있다.
