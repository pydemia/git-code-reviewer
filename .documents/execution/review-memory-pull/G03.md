기존 사용자 설정·계정·자동 실행 설정과 원래 checkout 및 P11 WIP를 보존한다. 전역 CLI 교체·강제 재로드·중앙 모델 대행·로컬 자료 업로드·신규 PR·추가 수집·runner·G04는 진행하지 않는다. 개발·검증 과정의 GCR 로그인·검증용 키 발급은 관리 작업이며 제품의 GCR 통신은 읽기 전용이다. Marketplace 게시는 한때 후속 요청으로 포함했으나 최신 사용자 요청에 따라 별도 작업으로 보류한다.

로컬 provider와 중앙 연결을 분리했다. Codex는 선택한 model·reasoning을 기존 catalog 검증과 실행 격리에 전달한다. OpenAI·Azure OpenAI·Anthropic·Gemini는 기존 API adapter와 OS credential을 재사용하며 캡처된 소스만 입력한다. CLI형 Claude Code·Gemini CLI·Antigravity는 기존 adapter 회귀 범위이며 이번 버전의 고정 소스 리뷰 지원으로 계산하지 않는다. API 오류·출력 잘림을 성공으로 바꾸지 않는다.

기존 연결 메뉴에 PR 이력 탐색을 추가했다. 원문·답글·본문 버전·thread 관측·지침을 reader 권한으로 읽으며 요청에는 중앙 ID와 cursor만 담는다. 암호화된 이력 캐시는 현재 연결 generation과 서명된 offline lease에 묶인다. 최대 128개의 페이지를 캐시하며 동기화 후 generation이 바뀌면 재조회가 필요할 수 있다.

리뷰는 파일·언어·심볼·branch로 지침을 로컬에서 선택한다. 자연어 적용 조건은 모델의 판단 문맥에 보존한다. 선택한 출처 연결 지침은 최대 5건, 건별 답글은 최대 10건을 원문과 함께 고정하며 답글 완전성을 표시한다. 지침 revision·본문 hash·관측 hash가 다르거나 캡처 도중 API revision이 바뀌면 해당 원문을 섞지 않는다. 결과에는 제공한 원문의 URL·ID·API revision·본문/관측 hash와 답글 hash를 기록한다. 별도 원문 승인 절차나 다운로드 코드 실행은 추가하지 않았다.

GCR의 기존 `selectSharedKnowledge` 동작은 유지했다. 자연어 조건 처리는 CD에서 사용하는 `selectCentralKnowledge`에 적용한다. GCR runtime 동작 변경이 없어 Helm 재배포하지 않았으며 PRISM-DEV는 alpha63/chart 0.10.59, Helm revision 73을 유지한다.

## 사용자 지정 Luna/high 검증

사용자가 `5.6-luna / high`로 변경을 요청했다. 기존 기본 Codex 계정을 그대로 사용하고 검증용 선택만 `gpt-5.6-luna / high`로 변경한다. 전역 계정·VS Code 설정은 수정하지 않는다. 앞선 Sol 결과는 실패 기록으로 보존한다.

추가 실제 CLI 리뷰 한도는 1회, 실행 제한은 300초다. 앞선 2회를 포함한 전체 한도는 3회다. 대상 파일과 PR #917·#915의 기존 자료는 그대로 사용하며, 온라인으로 미리 받은 원문·답글·지침을 유효한 signed offline cache에서 고정해 검증한다. 실제 호출 전에 새 선택의 bundled catalog와 loopback capability를 확인한다. Marketplace 게시·추가 수집·새 PR은 진행하지 않는다.

Luna/high의 [catalog·capability 확인](evidence/G03-luna-high-capability.json)은 통과했다. 실제 리뷰는 `2026-09-15T11:37:11Z`에 시작해 `11:42:10Z`에 `failed / timeout`으로 끝났다. `11:37:25Z` source, `11:37:28Z` base의 전체 5줄 읽기를 확인했고 원문·답글·지침의 고정 버전이 결과에 남았다. 완료 응답은 없었다. [Luna 실제 실행 증거](evidence/G03-native-model-luna-timeout.json).

Luna로 변경한 실행에서도 timeout이 발생했으므로 Sol의 추론 시간만을 원인으로 확정할 수 없다. 현재 executor는 실패 시 중간 CLI stdout/stderr를 보존하지 않아 모델·전송·CLI 중 어느 단계에서 지연됐는지 판별하지 못했다. 다음 검증에는 원문·토큰·비공개 추론을 저장하지 않는 CLI 이벤트 종류·시각 및 오류 코드 관찰이 필요하다. 이번에 기록한 실제 호출 한도 3회는 소진했으며 추가 호출은 하지 않았다. G03의 실제 모델 최소 리뷰 완료 조건은 충족되지 않았다.

검증용 reader key를 폐기하고 해당 로그인 세션을 종료했다. User Settings hash와 설치된 worker 바이트가 이전 검증과 같음을 재확인했다. [검증 후 상태](evidence/G03-post-account-verification.json). 실제 제품의 중앙 통신은 GET이며 [첫 실제 실행 시간대 서버 요청 기록](evidence/G03-live-central-requests.json)에서는 13건의 GET과 쓰기 0건을 관찰했다. 이 기록은 해당 시간대 서버 로그이며 검증용 credential에만 한정된 패킷 수집은 아니다. 모델 provider의 HTTP 요청 수는 집계하지 않았다.

이번 재개 작업의 CD 변경은 검증용 signed cache 사전 조회와 시간 제한 조정이며 `0b74ebc3a2c6d2f6410d4d4ccc1fa243536a3571`로 commit·push했다. 제품 코드·공통 artifact·VSIX 바이트는 그대로이므로 재빌드·재설치·Helm 재배포는 하지 않았다. Marketplace와 G04는 진행하지 않았다.

## CLI 지연 진단 재개

Goal 재개에 따라 반복 timeout의 원인을 확인한다. CD의 수동 검증 전용 wrapper가 설치된 worker를 그대로 로드하고 CLI stdout/stderr에서 허용된 이벤트 종류·시각·도구 이름과 분류된 오류 코드만 보존한다. 실행 인자·stdin·원래 스트림은 바꾸지 않는다. 원문·인증 정보·비공개 추론·자유 형식 오류 메시지는 기록하지 않는다. 합성 child-process 검사로 스트림 보존과 비밀 canary 비저장을 확인했다. wrapper는 제품·VSIX에 포함하지 않는다.

다음 실제 CLI 리뷰는 `gpt-5.6-luna / high`로 1회, 최대 180초다. 기존 기본 Codex 계정, 동일 합성 BlockUpdateRequest 파일, PR #917·#915와 기존 활성 지침, signed offline cache를 사용한다. 앞선 3회와 구분해 네 번째 시도로 기록한다. 이 시도는 관찰 경로를 추가한 원인 진단이며 실제 완료를 확인하지 못하면 성공 검증으로 처리하지 않는다. 진단 결과 없이 자동 재호출하지 않는다.

네 번째 시도는 180초 후 timeout으로 끝났다. 실제 CLI 이벤트에서 read_file 2건, search_code 1건, list_files 1건이 모두 완료된 뒤 최종 응답·추가 오류 없이 SIGTERM으로 종료됨을 확인했다. stdout 5,154바이트, stderr 0바이트였다. source bridge의 tool 응답이 멈춘 상황과는 구분된다.

다섯 번째 시도는 동일 Luna/high·계정·자료·입력·시간 제한으로 1회만 실행하되 수동 진단 wrapper가 `--output-schema`와 해당 경로 인자만 제외한다. 이는 최종 structured-output 경로의 영향을 구분하는 비교다. JSON 요구 프롬프트, 기존 localReviewResponse 검증, 고정 소스 읽기·권한·캐시 정책은 그대로 둔다. 이 비교가 통과해도 설치된 제품의 원래 인자와 다르므로 곧바로 G03 완료로 계산하지 않는다. 제품 수정·고정 artifact 전달과 설치된 코드 재검증이 별도로 필요하다.

다섯 번째 시도는 약 60.8초에 CLI `agent_message → turn.completed → exit 0`까지 도달했다. 하지만 `--output-schema`와 함께 형식 정의 자체도 모델 입력에서 빠져 최종 결과는 `invalid-output / invalid-schema`로 거절됐다. 실패의 성공 표시는 없었다. 이 결과만으로 서버의 특정 결함을 단정할 수는 없지만 다음 비교 대상을 CLI output-schema 경로로 좁혔다.

여섯 번째 시도는 동일 Luna/high·계정·자료·180초 제한으로 1회이며, 다섯 번째와 같이 CLI `--output-schema`를 제외하되 동일 JSON 스키마를 일반 프롬프트 마지막에 추가한다. 기존 응답 decoder와 고정 소스 근거 검증은 그대로 사용한다. 기존 형식 안내를 보존하면서 CLI 스키마 옵션의 영향을 구분한다. 총 실제 CLI 시도 한도는 이번 비교를 포함해 6회다.
