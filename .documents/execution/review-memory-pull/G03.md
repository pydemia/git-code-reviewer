## 구현 단위와 보존 범위

- C01: 중앙 연결과 독립적인 사용자 provider·model·reasoning 선택. 기존 Codex의 고정 소스 도구·실행 격리는 유지하면서 모델 카탈로그의 실제 지원을 검증한다. 다른 기존 adapter는 제공 가능한 입력과 제한을 확인하고 동일 리뷰 결과 계약에 연결한다.
- C02: 기존 인증·인가·캐시 경계를 재사용해 G02 이력 API의 목록·원문·답글·본문 버전·출처를 CD에서 조회한다. 서버 소유 ID·cursor·revision만 요청한다.
- C03: 내려받은 자료를 로컬에서 선택하고 리뷰 시작 시 자료·버전을 고정한다. 활성 지침·Skill과 과거 원문 관측을 구분해 입력하고 출처를 결과에 남긴다. 장애·권한 철회·모델 실패를 구분한다.
- D01: 공통 package를 고정 artifact로 CD VSIX에 포함하고 로컬 VS Code에 설치한다. 실제 Extension Host의 동작과 기존 열린 창의 적용 상태는 따로 기록한다. 변경이 없는 GCR runtime은 다시 배포하지 않는다.

기존 사용자 설정·계정·자동 실행 설정과 원래 checkout 및 P11 WIP를 보존한다. 전역 CLI 교체·강제 재로드·중앙 모델 대행·로컬 자료 업로드·신규 PR·추가 수집·runner·G04는 진행하지 않는다. 개발·검증 과정의 GCR 로그인·검증용 키 발급은 관리 작업이며 제품의 GCR 통신은 읽기 전용이다.

## 실제 호출 범위

G02의 `skccmygit/skax-successionX-backend` PR #917·#915와 활성 지침 `9ee94837-fd43-46f6-ac03-30bdfb8d3575`를 재사용한다. 새로운 GitHub 수집은 하지 않는다.

실제 모델 검증은 임시 저장소의 작은 BlockUpdateRequest 관련 예제로 최소 리뷰 1회를 실행한다. 최초 모델 호출 전 provider·model·reasoning과 호출 한도를 확정해 이 기록에 추가한다. 실패하면 원인을 먼저 확인하며 자동으로 재호출하지 않는다. 현재 사용자 설정에서 provider가 명시되지 않아 사용할 provider를 사용자에게 확인 중이다. 검증용 별도 VS Code 프로필에서 실행하며 기존 설정을 덮어쓰지 않는다.

합성 provider·transport 회귀와 실제 모델 실행 증거를 구분한다. 실행 기록에는 비밀번호·토큰·전체 원문을 복제하지 않는다.
