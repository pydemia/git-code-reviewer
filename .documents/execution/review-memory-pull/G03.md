## 구현 단위와 보존 범위

- C01: 중앙 연결과 독립적인 사용자 provider·model·reasoning 선택. 기존 Codex의 고정 소스 도구·실행 격리는 유지하면서 모델 카탈로그의 실제 지원을 검증한다. 다른 기존 adapter는 제공 가능한 입력과 제한을 확인하고 동일 리뷰 결과 계약에 연결한다.
- C02: 기존 인증·인가·캐시 경계를 재사용해 G02 이력 API의 목록·원문·답글·본문 버전·출처를 CD에서 조회한다. 서버 소유 ID·cursor·revision만 요청한다.
- C03: 내려받은 자료를 로컬에서 선택하고 리뷰 시작 시 자료·버전을 고정한다. 활성 지침·Skill과 과거 원문 관측을 구분해 입력하고 출처를 결과에 남긴다. 장애·권한 철회·모델 실패를 구분한다.
- D01: 공통 package를 고정 artifact로 CD VSIX에 포함하고 로컬 VS Code에 설치한다. 실제 Extension Host의 동작과 기존 열린 창의 적용 상태는 따로 기록한다. 변경이 없는 GCR runtime은 다시 배포하지 않는다.

기존 사용자 설정·계정·자동 실행 설정과 원래 checkout 및 P11 WIP를 보존한다. 전역 CLI 교체·강제 재로드·중앙 모델 대행·로컬 자료 업로드·신규 PR·추가 수집·runner·G04는 진행하지 않는다. 개발·검증 과정의 GCR 로그인·검증용 키 발급은 관리 작업이며 제품의 GCR 통신은 읽기 전용이다. 사용자의 후속 요청에 따라 Marketplace 게시를 G03 전달 범위에 추가했다.

## 실제 호출 범위

G02의 `skccmygit/skax-successionX-backend` PR #917·#915와 활성 지침 `9ee94837-fd43-46f6-ac03-30bdfb8d3575`를 재사용한다. 새로운 GitHub 수집은 하지 않는다.

실제 모델 검증은 임시 저장소의 작은 BlockUpdateRequest 관련 예제로 최소 리뷰 1회를 실행한다. 최초 모델 호출 전 provider·model·reasoning과 호출 한도를 확정해 이 기록에 추가한다. 실패하면 원인을 먼저 확인하며 자동으로 재호출하지 않는다. 현재 사용자 설정에서 provider가 명시되지 않아 사용할 provider를 사용자에게 확인 중이다. 검증용 별도 VS Code 프로필에서 실행하며 기존 설정을 덮어쓰지 않는다.

합성 provider·transport 회귀와 실제 모델 실행 증거를 구분한다. 실행 기록에는 비밀번호·토큰·전체 원문을 복제하지 않는다.

## 구현 및 전달 상태

GCR 소스 `d1facf9`에서 공통 패키지 `0.1.0-alpha.40`과 CD 내부 서비스 `0.1.0-alpha.35`를 만들었다. CD 제품 코드 `40e804c`, 패키징 commit `710e15c`에 연결된다. 세 공통 tarball과 CLI tarball을 깨끗한 소비자 환경에서 검증했고 CD는 workspace 경로 대신 버전이 고정된 vendor tarball에 의존한다. [전달 manifest](evidence/G03-delivery.json)에 전체 SHA와 artifact hash를 기록했다.

CD `203e2dd`에는 vendor source provenance와 고정 버전 검사도 포함한다. Marketplace README 링크는 이 commit의 `vscode-extension/docs/`로 고정했다. 최종 VSIX SHA-256은 `f60f2b07675dd4dfc3e117e1fd9f1dcf6a85b5051a9de9e0faf011b20fbde800`이다. 문서 링크를 고친 뒤 로컬 설치를 갱신했고 실행 코드는 Host에서 검증한 바이트와 동일하다.

로컬 provider와 중앙 연결을 분리했다. Codex는 선택한 model·reasoning을 기존 catalog 검증과 실행 격리에 전달한다. OpenAI·Azure OpenAI·Anthropic·Gemini는 기존 API adapter와 OS credential을 재사용하며 캡처된 소스만 입력한다. CLI형 Claude Code·Gemini CLI·Antigravity는 기존 adapter 회귀 범위이며 이번 버전의 고정 소스 리뷰 지원으로 계산하지 않는다. API 오류·출력 잘림을 성공으로 바꾸지 않는다.

기존 연결 메뉴에 PR 이력 탐색을 추가했다. 원문·답글·본문 버전·thread 관측·지침을 reader 권한으로 읽으며 요청에는 중앙 ID와 cursor만 담는다. 암호화된 이력 캐시는 현재 연결 generation과 서명된 offline lease에 묶인다. 최대 128개의 페이지를 캐시하며 동기화 후 generation이 바뀌면 재조회가 필요할 수 있다.

리뷰는 파일·언어·심볼·branch로 지침을 로컬에서 선택한다. 자연어 적용 조건은 모델의 판단 문맥에 보존한다. 선택한 출처 연결 지침은 최대 5건, 건별 답글은 최대 10건을 원문과 함께 고정하며 답글 완전성을 표시한다. 지침 revision·본문 hash·관측 hash가 다르거나 캡처 도중 API revision이 바뀌면 해당 원문을 섞지 않는다. 결과에는 제공한 원문의 URL·ID·API revision·본문/관측 hash와 답글 hash를 기록한다. 별도 원문 승인 절차나 다운로드 코드 실행은 추가하지 않았다.

GCR의 기존 `selectSharedKnowledge` 동작은 유지했다. 자연어 조건 처리는 CD에서 사용하는 `selectCentralKnowledge`에 적용한다. GCR runtime 동작 변경이 없어 Helm 재배포하지 않았으며 PRISM-DEV는 alpha63/chart 0.10.59, Helm revision 73을 유지한다.

- 검사 중 발견한 Codex의 불필요한 API 설정 읽기와 저장된 대화의 모델 변경 검사를 수정했다. 고정 artifact 검사에 새 버전 및 source provenance를 반영한 뒤 해당 검사와 이후 전체 그룹을 다시 실행했다. 실패했던 결과를 성공 증거로 계산하지 않았다.
