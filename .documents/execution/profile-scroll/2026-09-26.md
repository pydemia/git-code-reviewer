# 프로필 화면 스크롤 복구

데스크톱에서 `body`의 `overflow: hidden`을 사용하는데 `.profile-page`가 `min-height: 100dvh`만 지정해 내용 높이까지 늘어났다. 프로필 자체의 내부 overflow가 생기지 않고 바깥 스크롤은 막혀 하단이 잘렸다. 운영 화면의 2501×1217 viewport에서 프로필 높이·scrollHeight가 모두 2127px, scrollTop은 0이었다. 휠을 내려도 비밀번호 영역의 하단은 화면 밖 2018px에 머물렀다.

`reference-led-frontend`와 `agent-skills`의 `web-publishing`, `frontend-development`를 적용했다. 기존 `.admin-page`·`.guide-page`의 높이 제한과 스크롤 소유 구조를 reference로 삼아 `.profile-page`의 `min-height`를 `height: 100dvh`로 바꿨다. 프로필 내부 스크롤과 고정 header를 사용한다. 전역 body, 리뷰 workspace, 화면 구성, 계정·인증 코드는 변경하지 않았다.

## 검증

실제 frontend build를 읽기 전용 합성 profile API에 연결해 Chrome에서 검사했다. 운영 계정·설정·key를 fixture에 복사하지 않았다.

- 데스크톱에서 프로필 높이가 viewport에 제한되고 내부 scrollHeight가 더 길어진다. 표시 이름 입력란에서 Tab으로 마지막 비밀번호 변경 버튼까지 이동할 수 있다. 1360×800에서 마지막 버튼은 화면 하단에 표시되고 header는 top 0에 유지된다.
- 420×760에서 휠로 scrollTop 2113px까지 이동하고 마지막 버튼의 하단은 665px로 화면 안에 있다. document 높이는 760px로 별도 바깥 스크롤이 생기지 않으며 가로 넘침도 없다.
- web build(TypeScript 포함)와 변경 CSS Prettier 검사가 통과했다. 기존 Rollup annotation·bundle 크기 경고는 그대로다.
- CSS 선언을 그대로 비교하는 단위 테스트를 추가하지 않고 실제 브라우저의 이동·focus·좌표를 확인했다. 운영 검증은 배포 후 별도 기록한다.
