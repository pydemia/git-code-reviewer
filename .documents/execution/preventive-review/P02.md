## C02 암호화 local store

GCR `7a8cb6c`를 `origin/feat/preventive-review-platform`에 push했다.

`client-core`에 `LocalRecordStore`, `LocalKnowledgeStore`, `LocalHistoryStore`와 OS key adapter를 추가했다. Profile 공통과 repository/worktree scope를 구분한다. 실제 Git common directory·worktree의 canonical 경로에서 identity를 계산하며 동명 clone·linked worktree·profile을 분리하고 remote credential은 읽지 않는다. 경로를 옮긴 checkout은 명시적 가져오기로 자료를 이동한다.

Memory와 Skill의 본문·scope·revision/hash·출처·유효 기간을 저장한다. 생성·가져오기는 candidate로 시작하고 활성화는 별도 동작이다. 편집, 만료일 해제, 비활성화·보관·삭제, hash 검증을 거친 가져오기와 사용자 지정 새 파일로의 명시적 내보내기를 지원한다. Skill은 실제 Markdown 본문을 가진 review-only 자료이며 실행 권한을 만들지 않는다.

Managed Skill을 포함한 local 데이터는 AES-256-GCM으로 암호화한다. Key는 macOS Keychain 또는 Linux Secret Service에 저장하고 app data에는 opaque reference만 둔다. 디렉터리 0700·파일 0600을 검사하며 symlink·다른 owner·공유 권한을 거부한다. 기존 key/ref가 없거나 잠겼을 때 새 key로 덮거나 평문으로 저장하지 않는다. 기본 저장 위치는 repository 바깥의 OS application data이며 명시적 plaintext export도 0600의 새 파일만 생성한다.

동시 수정은 expected revision과 불변 commit marker의 exclusive hard link로 제어한다. 오래된 수정은 conflict다. 삭제 후 marker를 유지해 오래된 writer가 이전 revision을 재생성하지 못하게 한다. 실패한 staging은 reader가 선택하지 않으며 commit 뒤 fsync 실패는 commit-unknown으로 반환한다. Tombstone commit과 body 정리 실패를 구분하고 reader는 동시 삭제로 선택한 body가 없어지면 새 committed head를 확인한다. 임의의 이전 revision으로 fallback하지 않는다. OS 파일 자체의 rollback 방지나 저장 매체의 secure erase를 주장하지 않는다.

리뷰의 partial/failed/cancelled 상태와 user/assistant 대화 원문을 그대로 보관한다. 보존 설정도 scope별 암호화 저장소에 저장하며 기본은 리뷰·대화 각각 90일/1000개다. 기간은 1–3650일, 개수는 1–10000개로 설정할 수 있다. 만료·개수 초과 이력 정리는 local Memory·Skill을 건드리지 않는다. 새 chat revision과 경합하면 최신 대화를 삭제하지 않는다. 이 단계의 chat은 저장 archive이며 실행·질문·checkpoint 기능은 P08에 남아 있다.

## C03 불변 source capture

GCR `9ba01de`를 `origin/feat/preventive-review-platform`에 push했다.

`captureLocalSource`는 index 또는 저장된 working tree와 base를 고정하고 `LocalSourceSnapshot`의 읽기 API로 반환한다. Base ref는 한 번 commit으로 해석한 뒤 HEAD와의 merge-base를 사용한다. Index와 working tree의 부분 stage를 구분하며 untracked는 명시한 파일만 포함한다. 삭제한 파일은 base 본문, rename은 이전 경로와 source 본문을 유지한다. 관련 파일도 시작 시 한도 안에서 함께 읽는다. 이후 `readFile`·`readLines`·literal `search`는 Git이나 원래 filesystem에 접근하지 않는다.

기존 GCR git-engine의 안전한 Git 실행·경로·blob 검증과 CD의 임시 index·정확한 tree entry filtering을 공통 package 경계에 맞게 옮겨 보완했다. 출처와 Apache-2.0 attribution은 source 및 package README에 남겼다. 사용자 index·object 저장소·checkout을 변경하지 않고 생성 object와 index는 0700 임시 디렉터리에만 쓴다. 반환 전에 임시 디렉터리를 제거한다. Raw source를 평문 영구 cache로 저장하지 않는다.

각 본문의 실제 UTF-8 bytes, SHA-256, Git blob ID, line count와 side를 기록한다. Working tree는 BOM·CRLF·filter 변환 전후의 실제 bytes를 보존하므로 Git base와 normalization 차이도 변경으로 보일 수 있다. 파일을 읽는 사이 내용·metadata가 바뀌거나 캡처 중 HEAD·ignore 판정이 바뀌면 snapshot-changed로 실패한다. 여러 파일을 관측하는 capture interval이며 filesystem 전체의 원자적 transaction을 주장하지 않는다.

기본 한도는 파일당 1 MiB, 양쪽 source 합계 32 MiB/10,000개, 경로 50,000개, capture 30초다. Index 입력은 regular non-symlink 파일만 최대 64 MiB로 읽으며 FIFO를 기다리지 않는다. Git 명령과 본문 read도 각각 크기·시간을 제한한다. 경로·비공개·생성물·ignore·binary·잘못된 UTF-8·LFS pointer·submodule·크기 초과는 limitation으로 남긴다. 비교 한쪽이 누락되면 반대쪽을 허위 추가·삭제 diff로 만들지 않는다. Unmerged·손상·missing object로 Git 준비를 못 하면 working tree로 fallback하지 않는다.

Ignore는 repository의 `.gitignore`·`.git/info/exclude`와 별도 명시한 deny pattern으로 판정한다. Global/system Git config는 읽지 않는다. Pattern은 `*`, `?`, path component `**`, 경로/디렉터리 prefix만 지원하며 부정·문자 class·escape는 거부한다. Working tree 부모가 symlink면 ignore 파일을 따라가지 않고 해당 경로의 제한을 기록한다. 이 조건은 index 조회에도 적용한다. C07의 기존 제외 설정 adapter는 이 지원 범위를 확인해야 한다.

초기 실제 Git 검사에서 clean filter가 호출되는 canary를 발견했다. Index write와 diff 명령에 빈 working tree를 제공하고 [자동 index refresh](https://git-scm.com/docs/git-config)를 끈 뒤 같은 검사가 통과했다. Fsmonitor·hook·외부 diff/textconv·lazy fetch·Git protocol도 차단한다. 이 처리는 source capture 경계이며 모델 CLI의 OS 격리를 대신하지 않는다. C05에서 실행 adapter를 별도로 검증한다.

Source API는 동기식이며 UI event loop 밖에서 실행해야 한다. Snapshot 본문은 현재 process 메모리에 있으며 metadata getter는 복사본을 반환한다. History에 Git ID만 저장하면 제거된 임시 tree를 복구할 수 있다고 가정하지 않는다. 후속 consumer는 허용된 고정 view를 보관하거나 source unavailable을 표시해야 한다. Search는 관련 문자열 후보이며 semantic call graph나 결함 입증이 아니다.

## C04 context와 실행 정책

GCR `4a263c1`을 `origin/feat/preventive-review-platform`에 push했다.

`resolveReviewMode`는 mode만 읽고 기본값을 standalone으로 정한다. 남아 있는 중앙 URL·token·cache에는 접근하지 않는다. Centralized를 명시하면 아직 미지원인 상태를 반환하고 local store도 읽지 않는다. 이 resolver에 network port는 없다.

`resolveLocalContext`는 application 소유의 built-in review Skill과 활성화된 local Memory·review-only Skill을 고정한다. Profile·repository/worktree scope, 본문 hash, 만료일, 경로·언어·branch·symbol 적용 조건을 검사한다. 적용 조건의 여러 차원은 같은 선택 파일에서 충족해야 한다. Symbol은 literal 후보 확인이며 semantic 분석이 아니다. 파일 본문·Skill이 도구, provider, 업로드 권한을 만들거나 과거 finding을 일괄 억제하지 못하도록 application 지침과 자료를 구분한다.

필수 자료를 먼저 선택하고 repository 자료를 profile 자료보다 우선한다. Store는 한 번에 한 record씩 검증하며 기본 scan 한도 5,000개/16 MiB, context 자료 한도 64 KiB를 적용한다. Scan 한도 도달은 부분 index를 ready로 처리하지 않고 needs-context다. 선택에서 빠진 자료의 이유와 필수 source·knowledge 가용성도 context identity에 포함한다. Store 오류·scope 혼입·변조는 private 본문이나 원래 오류 문자열을 노출하지 않고 unavailable로 처리한다. 비동기 읽기 중 caller의 입력이나 이후 knowledge가 바뀌어도 이미 준비한 context는 변하지 않는다.

Snapshot에 실제 repository/worktree identity와 시작 branch를 추가했다. Context와 policy는 본문 hash뿐 아니라 이 origin을 대조하므로 동일한 내용을 가진 별도 clone에 승인을 재사용할 수 없다. Capture 중 HEAD가 같더라도 branch가 바뀌면 snapshot-changed다.

`resolveLocalExecutionPolicy`는 trusted workspace와 현재 application/user가 제공한 source·executor 승인을 요구한다. 승인은 client, executor ID, model, config hash와 선택 source 범위를 묶는다. 관련 source·base·local knowledge를 각각 허용해야 하며 필수 근거가 범위 밖이면 needs-context다. 승인 입력은 암호학적 grant가 아니므로 repository 설정·Skill·remote 자료에서 역직렬화해 발급하면 안 된다. 후속 consumer가 현재 승인과 철회를 관리해야 한다.

실행기는 fixed-source-only 격리, 취소, timeout, 하위 process 정리를 지원해야 ready가 된다. 미확인·미지원 capability는 unavailable이며 다른 모델이나 계정으로 전환하지 않는다. 도구는 고정 source의 `list_files`, `read_file`, `search_code`만 허용하고 결과 enforcement는 advisory다. 출력 token 상한을 요청했는데 실행기가 지원하지 않으면 실행을 거부한다.

Run budget은 기본 model call 2회, 120초, source 1 MiB, tool call 100회이며 실패한 시도도 예약을 소비한다. Source·tool 호출과 단조 시계를 검사하는 ledger를 제공한다. `outputTokensPerCall`은 선택한 adapter에 전달할 호출당 상한이며 전체 run의 실제 사용 token을 측정한 값이 아니다. C05에서 실제 실행 경로가 ledger와 process 제한을 적용해야 한다. Project별·다중 process persistent quota는 P07 범위다.

## C06 CLI와 공통 리뷰 실행

구현, 정적·회귀 검증과 설치본의 실제 모델 표본 검증을 완료했다.

`apps/cli`에 `status/context/review/result/history`와 Memory·Skill의 생성·조회·편집·활성화·비활성화·보관·삭제·가져오기·내보내기 명령을 추가했다. 개인 지식은 기본 `default` profile의 repository/worktree scope이고 `--scope profile`은 Git 밖에서도 사용한다. 입력 JSON은 최대 2 MB, regular non-symlink 파일 또는 stdin으로 받는다. Create/import는 candidate이며 활성화는 별도 명령이다. Revision을 명시하지 않은 수정·활성화·삭제와 stale revision을 거부한다. Export는 명시한 새 0600 파일에만 평문을 만들고 import는 원본 hash를 검사해 새 scope/ID를 부여한다. 이력을 읽을 때 모델을 호출하거나 지식을 자동 활성화하지 않는다.

공통 `runLocalReview`는 core에 두고 CLI에서 executor와 조립한다. 모델 응답은 제한된 별도 decoder로 읽으며 identity·enforcement·exception·test 결과를 모델에게 맡기지 않는다. `read_file`이 반환한 임의의 `readId`, 경로·side·hash·범위·excerpt hash를 기록하고 응답의 참조를 대조한다. 선택 source/base의 전체 줄과 필수 source가 실제 반환되고 응답에 인용되어야 완료로 처리한다. Truncated read, 누락된 파일, 위조 ID, 다른 model, 선택 범위 밖 anchor, 필수 질문, 반증 충돌, 예산 초과, 취소 후 도착한 응답은 clean completion이 아니다. Anchor 검증과 source 추론은 분리하고 테스트를 실행하지 않은 report에 test-confirmed evidence를 만들지 않는다. Prompt와 source 반환 bytes를 같은 전송 예산에 넣으며 논리적 invocation은 한 번이다.

최종 client library는 `0.1.0-alpha.9`, CLI는 `0.1.0-alpha.3`이다. CLI alpha.1 뒤 비TTY stdin 취소 경로를 보완했다. ### C06 최종 설치본의 실제 리뷰

## C07 CD source 전달과 TypeScript 표본 보정

CD `5afe1d4c6a7ea737c0ab89ca6882abc8cd98da75`는 GCR `400b54a`에서 전달한 세 library alpha.9를 소비한다. ## C08 CD credential migration 전달

CD `37c472d6ae36cd3bdeed8aef7bb82ae7590e73e1`에서 모델 API credential을 `com.commitdefender.model-credentials.v1` OS service와 별도 `model-credentials/v1` 암호화 디렉터리로 옮기는 경로를 구현했다. User/Workspace Settings와 hook의 기존 평문은 명시적 migration에서 암호화 record와 OS key, 저장된 reference를 다시 읽어 확인한 뒤에만 제거한다. 새 hook JSON은 참조만 보관하고 runtime은 기존 plaintext API key를 fallback으로 사용하지 않는다.

Reference는 profile·provider·endpoint·model/deployment·Azure API version을 확인한다. API redirect와 key가 포함된 error output을 제한했다. Native password 입력, 저장한 key 재선택, expected revision을 확인하는 명시적 교체도 제공한다. 기존 Codex 등 account CLI 로그인은 이 migration 대상에 포함하지 않는다. Hook의 공통 core·trigger 연결은 P07에 남아 있다.

CD 전체 자동 검사 123개가 통과했고 후속 명시적 교체·revision 검사까지 credential suite 13개를 Node 25/18에서 통과했다. 실제 macOS Keychain의 합성 key로 VS Code 1.135.0 및 1.90.2 Extension Host에서 요청한 뒤 Host 종료 후 별도 단일 hook bundle이 같은 credential을 사용했다. Localhost 합성 API 요청은 총 4회, 실제 모델 호출은 0회다. Endpoint 변경과 missing OS key에서는 요청을 거부했으며 테스트가 생성한 자료는 정리했다. 첫 실행의 macOS socket path 길이 오류도 실패 증거로 보존했다.

개발용 VSIX `43549161627348aa073d949d4c034748ed2021e39678d3a7748b2dd673c12c2a`는 ignored `artifacts/commit-defender/P02-C08`에 보존했다. 고정 library alpha.9와 CLI alpha.3 artifact는 바꾸지 않았다. C08의 세부 검증·한계는 CD의 `P02-C08-source-checkpoint.json`과 `P02-C08-vsix-contents.json`을 따른다.
