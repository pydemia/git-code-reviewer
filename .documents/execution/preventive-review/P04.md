# P04 — Client 인증과 credential broker

## 2026-09-14 — Repository 범위 API key와 HTTP 동기화

P04-C01의 API key 저장·bearer 인가와 C02의 웹 key 관리 API, P06 transport를 연결했다. 0041 migration은 기존 사용자·session·grant를 변경하지 않는다. Key는 user·server·tenant·명시적 repo 집합·read scope·기존 credential epoch와 발급 identity에 묶인다. 원문은 생성 응답에 한 번만 반환하며 DB·목록·감사에는 남기지 않는다. Local password timestamp는 DB 정밀도를 보존하고 SAML freshness 만료 503과 확인된 epoch 철회 403을 구분한다.

실제 PostgreSQL과 Fastify HTTP listener에서 local 로그인→키 발급→서명한 세 bundle 다운로드→암호화 cache 활성화→304→키 폐기→403과 cache 사용 중단을 검증했다. 별도 HTTPS fixture는 개발 CA 신뢰, 잘못된 인증서/hostname 거부, redirect에 credential 미전송을 확인한다. 모델 호출은 없다.

Bearer 요청은 웹 쿠키·development 사용자로 fallback하지 않으며 등록된 지식 조회 route만 허용한다. 등록 순서가 바뀌며 발견한 SAML 오류 envelope 회귀는 공통 error handler를 route 등록 전 설치하도록 수정했다. 수정 후 실제 SAML route·DB 회귀를 다시 통과했다. [운영 계약](../../../docs/operations/client-api-keys.md)과 [증거](evidence/P04-client-api-keys.json)에 범위와 테스트를 기록한다.

Helm `clientApiKeys.enabled`는 기본 false다. 이번 checkpoint에서 PRISM-DEV는 alpha.41·chart 0.10.39·migration 40이며 client key는 활성화하지 않았다. Web key 관리 UI와 CD/CLI 연결 UI·OS credential broker, PKCE/device/refresh family, 중앙 review context와 두 환경 실제 리뷰, 새 client artifact·서버 배포가 남아 있다. C01–C07 전체 완료로 집계하지 않으며 P00–P13 goal은 계속 진행한다.
