# P06 — 중앙 연결·원자적 동기화·fallback

## 2026-09-14 — 암호화 snapshot 동기화 core

P06-C02의 동기화 core와 C01의 명시적 server/audience·키 pin 검증, C03의 lease·연결 폐기 primitive를 구현했다. `KnowledgeTransport`는 주입하는 인터페이스이며 실제 HTTP 인증 adapter나 CD/CLI 중앙 리뷰를 구현했다는 의미는 아니다. 전체 P00–P13 goal은 진행 중이다.

서명한 manifest의 세 component를 모두 검증한 뒤 암호화 index의 active 참조와 실행권 해제를 단일 revision compare-and-swap으로 기록한다. 동일 hash는 재사용하며 개인 bundle만 변경되면 개인 자료만 내려받는다. 활성 자료를 손상된 이전 버전으로 대체하거나 다운로드한 일부 component만 섞지 않는다. 저장 위치와 OS key reference는 기존 local memory/history와 분리한다.

실행권에는 만료 시각과 generation이 있다. 별도 Node 프로세스의 경쟁·만료 후 인계·늦은 이전 프로세스 응답을 실제 프로세스로 검증한다. 테스트 credential port에는 테스트에서 생성한 키만 주입한다. 운영 OS credential store나 Linux 설치 환경 검증을 이 테스트로 대체하지 않는다.

확인된 권한 revision·revocation floor는 다운로드보다 먼저 저장한다. 그 기록에 실패하거나 401/403 이후 상태 저장에 실패하면 남아 있는 실행권이 다른 프로세스의 cache read도 차단한다. 실행권 만료는 새 동기화의 인계만 허용하며 offline cache의 사용 권한을 복원하지 않는다. 동기화 중 read도 `busy`이므로 host는 재시도 상태를 처리해야 한다. 정상 실패 후에는 실행권을 해제하고 기존 snapshot의 lease·floor를 검사한다. 304는 서명된 기존 lease를 연장하지 않는다.

취소는 활성화 쓰기 시작 전 확인하며 활성화가 이미 commit된 경우 되돌리지 않는다. `commit-unknown`은 실패로 단정하거나 이전 pointer로 복원하지 않고 재조회한다. ENOSPC 테스트는 staging·activation·권한 상태 쓰기에 오류를 주입한 검증이며 실제 디스크를 가득 채운 시험은 아니다. 중단된 staging·삭제 실패로 남은 암호문은 후속 cleanup 대상이다.

검증 결과와 source hash는 [증거 파일](evidence/P06-central-cache.json)에 기록한다. API 사용과 오류 의미는 [client-core README](../../../packages/client-core/README.md)에 정리했다.

다음 구현 범위는 remote→명시적 repository 매핑, P04 client 인증을 사용하는 HTTP transport, 주기·수동·review freshness 동기화와 제한적 credential 갱신, 공통 중앙/로컬 review context·진행 중 철회, CD UI 및 macOS/Linux 실제 중앙 리뷰다. P05의 높은 sequence rollback·출처 상세·실제 sync 보고도 남아 있다. 이 checkpoint에서는 client package를 재배포하거나 PRISM-DEV 서버를 재배포하지 않았다.

## 2026-09-14 — 중앙 review context와 실행 중 권한 검증

`resolveCentralContext`를 추가하고 기존 고정 source/base·실행 승인·review runner에 연결했다. 정확한 server/audience와 repository/profile/worktree의 암호화 cache만 사용한다. Built-in·필수 local 자료·중앙 정책·Skill·선택 메모리를 한 예산 안에서 구성하고, 필수 내용이 빠지면 `needs-context`로 남긴다. Model 호출에는 중앙 자료와 local 자료를 구분해서 전달하며 `allowKnowledge` 승인을 요구한다. Context hash에는 mode, audience, source, manifest/세 component, local 항목, 적용 범위·예외·우선순위·누락을 고정한다.

메모리의 grouping identity를 v2 bundle에 추가했다. 적용 범위가 맞는 같은 `aggregationKey`의 collective가 같은 파일의 personal 판단보다 우선한다. Personal은 겹치지 않는 파일에 원문 판단을 유지하고, 겹치는 파일에는 source 참조와 counter-evidence만 남긴다. Branch·경로·언어·lexical symbol/contract 조건과 criterion 예외의 기간·파일 범위를 적용한다. Local 자유 서술에는 공통 grouping identity가 없으므로 별도 보완 자료로 유지한다. Local 문장의 의미상 충돌 판정이나 기존 서버 PR 분석의 legacy memory selector 교체까지 완료한 것은 아니다.

Runner는 모델 시작 전·source tool 호출 전·응답 처리 후에 원래 cache의 권한을 검증하고 실행 중에는 100 ms 간격으로 변경을 관측한다. 동기화 실행권이 있는 동안 추가 source read를 보류한다. 권한 revision·critical floor 상승, 연결 폐기, context 만료, 만료된 미해결 동기화 실행권을 확인하면 리뷰를 취소한다. Abort를 무시하는 executor의 늦은 응답을 기다리지 않으며 종료된 리뷰의 tool 호출도 거부한다. 일반 갱신은 기존 prompt로 끝내고 `superseded`와 사유를 남긴다.

Accepted sequence와 explicit revocation floor를 index에서 분리했다. 기존 index는 이전 floor를 보수적으로 유지한다. 현재 서버는 모든 새 release의 sequence를 revocation floor로 내보내므로 실제 서버 갱신은 여전히 진행 중 리뷰를 취소한다. 일반 갱신의 stale 처리는 floor를 유지하는 합성 signed manifest로 검증했다. 서버 release의 일반/critical 분류는 후속 구현이다.

Migration 0042는 기존 scope를 v2 재발행 대상으로 등록하고 v1 artifact로 발행 요청을 완료 처리하는 구버전 worker를 차단한다. Manifest API는 v2 artifact 세 개가 준비된 경우에만 v2 계약을 제공한다. Grouping identity를 approval fingerprint에 포함하므로 기존 projection과 grouping이 바뀐 자료는 명시적인 재승인이 필요하다. 기존 immutable history를 삭제하거나 자동 승인하지 않는다. 운영 적용 절차는 [배포 문서](../../../docs/operations/review-knowledge-distribution.md)에 기록했다.

실제 임시 Git 저장소·고정 index/base, 합성 Ed25519 bundle, 임시 암호화 cache, 합성 executor와 별도 로컬 PostgreSQL에서 검증했다. Source 읽기는 실제 core port를 사용하며 외부 모델은 호출하지 않았다. 운영 OS credential store, 설치한 Commit Defender/CLI의 중앙 리뷰, 실제 PRISM-DEV v2 배포를 검증한 결과는 아니다. 검증 보고서와 source hash는 [증거 파일](evidence/P06-central-review.json)에 기록한다.

P06-C04의 공통 client core 구현 checkpoint이며 전체 P06 완료가 아니다. 다음 범위는 서버의 일반/critical 갱신 분류·기존 서버 resolver 공통화, API key 관리 UI·OS broker·remote repository mapping·CD/CLI 중앙 모드 연결, 실제 배포 및 설치 client 리뷰다. 이번 변경으로 PRISM-DEV Helm revision 53·alpha.41·migration 40, Keycloak revision 2와 DB TLS를 변경하지 않았다. 전체 P00–P13 goal은 계속 진행 중이다.

## 2026-09-14 — 첫 연결 발행 대기와 실제 PRISM-DEV CD 리뷰

앞선 실서버 검증에서 드러난 최초 연결 실패를 공통 core에서 보완했다. 실제 HTTP 503 manifest 응답만 1/2/4초 상한의 증가 간격과 jitter로 재시도한다. 초기 sync의 전체 제한은 60초이고 최대 재시도는 15회다. cache 실행권과 registry pending 상태를 유지하며 세 component가 검증되기 전에는 활성화하지 않는다. 취소·timeout·권한 거부·잘못된 응답에서는 연결을 종료하고 등록 중인 key를 정리한다. 일반 sync의 재시도 정책은 변경하지 않았다.
