## 구현 현황 대조

- GCR의 기존 서버·웹, tenant/repository 인가, account registry, 개인/집단 memory·Skill, 리뷰·대화·PR 게시 기능을 유지한다. 현재 인증 모드는 `development/local/oidc/proxy`이며 SAML과 client 전용 key/PKCE/device flow는 미구현이다.
- DB migration은 31개이며 마지막 파일은 `0031_registry_deletion.sql`이다. 이 확인은 파일 현황이며 운영 DB 적용 검증은 배포 단계에서 별도로 수행한다.
- `packages/client-contract`, `client-core`, `client-executors`, `apps/cli`, `apps/mcp`는 착수 시 존재하지 않는다. Local store·불변 source snapshot·signed bundle sync·공통 자동 리뷰 scheduler는 새로 구현한다.
- CD 기준에는 API provider와 Codex/Claude Code/Gemini CLI/Antigravity account adapter가 있다. Extension과 hook은 Node 18 target으로 bundle한다. `npm test`는 provider test만 실행한다. 실제 모델, 읽기 범위, 취소와 Extension Host는 이번 phase에서 별도로 검증한다.
- CD 선행 결함은 P01의 수집 정책, staged source, 실패 상태, 출력 경로·Markdown trust, backend 경계 순서로 처리한다. 새 기능을 legacy hook 차단 정책과 섞지 않는다.

## P00-C03 평가 입력

`tests/fixtures/preventive-review/`에 Python 부분 cache, TypeScript 삭제 권한, Python/TypeScript API 전환을 결함·수정·정상·반증으로 나눈 12개 synthetic 사례를 추가했다. 기대 판단·필수 근거 파일·before/after Git tree·정의 SHA-256은 `manifest.json`으로 고정했다. 실제 PR #953 source는 확인하지 않았으므로 해당 PR의 원문이나 익명화 결과로 표시하지 않는다.

Python 실행·TypeScript transpile 후 실행·혼합 언어 요청/route 대조가 fixture label과 일치했다. Partial stage와 working-tree-only TODO, 삭제·rename 후 남은 consumer, worktree별 index, 두 push ref 및 삭제 ref를 실제 임시 Git repository로 재현했다. `pnpm exec vitest run tests/fixtures/preventive-review/catalog.test.ts`의 18 tests와 ESLint가 통과했다. 최초 manifest 생성 테스트는 12개 repository의 누적 작업 때문에 기본 5초 제한을 넘겼다. 이 생성 검사만 30초로 제한을 조정하고 manifest 갱신 없이 전체 18개를 다시 통과했다.

이는 평가 입력 자체의 검증이다. 실제 모델의 source 조회·판단과 제품의 snapshot/trigger 동작은 아직 검증하지 않았다. 다음은 P00-C04의 Extension Host·executor 확인이다.
