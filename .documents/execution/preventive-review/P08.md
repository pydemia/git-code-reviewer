# P08 실행 기록

## P08-C01: 로컬 리뷰 대화와 질문 checkpoint

구현 commit: `b55c98d` (`feat: persist interactive local review conversations`).

`client-contract`에 대화·turn·질문·인용·예산 계약을 추가했다. Web `chat-run`의 질문 길이와 선택지 제한, 상태 어휘를 로컬 계약에 옮겼으며 서버 session/account ID와 DB 의존성은 포함하지 않았다. 로컬 인용은 기존 `SourceLocation`을 사용한다.

`ReviewConversationStore`는 원래 리뷰 보고서·고정 source·실행 identity·대화·질문·재개 상태를 하나의 암호화 CAS record로 저장한다. 기존 단순 chat archive와 namespace를 분리했고 profile/repository/worktree와 중앙 audience를 검사한다. 다른 중앙 사용자나 standalone 선택에서는 해당 대화를 조회·목록·삭제할 수 없다. Source와 context identity가 달라지면 기존 대화의 실행을 거부한다. 저장된 identity나 사용자 답변으로 실행 권한을 발급하지 않는다.

`runReviewConversation`은 현재 권한을 확인한 뒤 한 worker만 실행한다. Codex `converse`에만 `ask_user`를 노출하며 질문·call ID·사용 예산을 저장한 뒤 프로세스를 취소한다. 사용자 응답은 같은 turn을 queued로 바꾸고 다음 호출이 새 격리 프로세스에서 저장된 대화를 재구성한다. Provider thread, 비공개 추론, credential은 저장하지 않는다. 이전 단계의 인용 ID는 재사용할 수 없고 현재 단계에서 반환된 `read_file` 범위만 인용할 수 있다. Search 결과를 직접 소스 인용으로 취급하지 않는다.

모델 호출·전송 바이트·tool 호출·실행 시간은 응답 후에도 같은 turn의 예산에서 차감한다. 사용자 응답 대기는 실행 시간을 사용하지 않는다. 결과가 확인되지 않은 running 작업은 예약을 유지하며 명시적 `interrupt`가 failed/interrupted로 닫을 뿐 모델을 다시 호출하지 않는다. 중복 응답은 같은 답이면 같은 revision을 반환하고 다른 답은 거부한다. 취소·종료·삭제 뒤 도착한 결과나 질문은 이전 CAS revision으로 덮어쓸 수 없다.

Host가 호출하는 `prune`는 기존 chat retention 설정을 사용한다. 24시간 동안 답하지 않은 질문을 expired로 종료하며 queued/running 실행은 나이만으로 삭제하지 않는다. UI의 startup/terminal 변경에서 이 메서드를 호출하는 연결은 P08-C02에 포함한다.

## 검증

대화 16개, 암호화 record·기존 history·source bridge·Codex 격리·기존 리뷰 runner를 합쳐 관련 6개 suite의 75개 검사가 통과했다. Source build, 신규 테스트 TypeScript 검사, 변경 파일 ESLint, diff 공백 검사를 통과했다. 별도 consumer의 패키지 설치/import는 Node 22.23.2에서 확인했다.

실제 계정의 사전 검증에서는 `gpt-6-astra / xhigh`가 질문을 저장했고 해당 host 프로세스가 종료됐다. 다른 host 프로세스에서 암호화 기록을 열어 답변을 저장한 뒤 같은 conversation/turn/source/context로 재개했으며 source·base·caller 인용 4개와 completed 응답을 얻었다. 두 단계 사이 작업 파일을 바꿨지만 저장된 소스로 응답했다. 검증 fixture와 전용 OS key를 정리했다. 이 사전 검증은 패키징 전 source 경로이며 최종 artifact 검증과 구분한다.

## 최종 패키지 검증과 전달

공통 패키지 `0.1.0-alpha.23` 세 개를 생성하고 별도 consumer에 설치했다. 설치한 contract/core/executors의 dist 파일 48/102/21개가 빌드 결과와 각각 byte 단위로 일치한다. 패키지 SHA-256과 검증 결과는 [P08-conversation.json](./evidence/P08-conversation.json)에 기록했다.

설치 패키지에서도 실제 `gpt-6-astra / xhigh` 대화를 검증했다. 첫 host(PID 36819)는 source/base/caller를 4번 읽고 `ask_user` 질문 1개를 저장한 뒤 awaiting_input으로 종료했다. 첫 프로세스가 종료된 후 작업 파일을 변경했다. 새 host(PID 45449)가 암호화 기록을 열어 중복 응답의 revision 불변을 확인하고 같은 conversation/turn/source/context로 재개했다. 두 번째 단계에서도 고정 source를 4번 다시 읽고 인용 4개를 포함한 completed 응답을 반환했다. 대화 모델 호출은 합계 2회이며 첫 리뷰 생성 호출은 이 대화 예산에 포함하지 않는다. 모델은 테스트 명령을 실행하지 않았다. 두 host의 종료 후 전용 OS key와 fixture를 정리했다.

이 checkpoint는 공통 패키지의 로컬 배포와 독립 consumer 검증이다. Commit Defender 화면·VSIX, CLI, PRISM 서버 및 공개 registry 배포는 이번 변경에 포함되지 않는다.

## 남은 연결과 완료 범위

현재 범위는 P08-C01의 공통 실행·저장 경로다. P08 전체를 완료한 것은 아니다. 중앙 연결의 실제 철회/동기화와 대화 재개를 결합한 검증, Commit Defender 화면·worker·history 연결, CLI/MCP, feedback 제출·승인·재동기화, Skill 배포가 남아 있다. 기존 웹 대화의 모든 상태와 서버 API를 이 로컬 엔진으로 교체하지 않았다.

P08-C02에서는 리뷰 worker가 snapshot을 닫기 전에 대화용 고정 source를 보존하고 history/finding에서 대화를 연다. 과거 보고서에 고정 source가 없는 경우 현재 작업 파일을 과거 소스로 간주하지 않는다. 중앙 대화는 기존 중앙 history의 connection별 data directory와 현재 audience를 사용한다. 실행 설정이 바뀌면 기존 대화에 새 설정을 몰래 적용하지 않는다.

P07의 통합 trigger 실행·복구 등 잔여 조건과 P09–P13은 계속 전체 goal에 남아 있다.
