# P07 실행 기록

## 공통 실행 소유권과 저장된 결과 재사용

CLI의 수동 리뷰를 암호화한 실행 기록에 연결했다. 같은 profile·repository·worktree 안에서 source/base/context/knowledge/review profile/executor/model/tool 설정이 같으면 사유를 합치고 한 프로세스에만 실행권을 준다. 중앙 동기화의 `lastSynchronizedAt`은 내용 변경이 아니므로 중복 판단에서 제외한다. 실행 모드·fallback 사유·중앙 audience·connection은 유지한다.

- `queued → claimed → running → finished`를 CAS로 기록한다. 기본 lease는 30초, 실행 중 갱신은 10초다.
- 실행 전 `claimed` 상태에서 종료된 프로세스는 lease 만료 후 교체할 수 있다. `running` 상태의 lease가 만료되면 `interrupted`로 남긴다. 프로세스 종료만으로 모델 작업의 종료를 단정하거나 재호출하지 않는다.
- 대기하는 호출자를 취소해도 실행 소유자의 작업은 취소하지 않는다.
- 저장된 결과를 재사용할 때도 현재 중앙 접근 권한과 snapshot 상태를 확인한다. 다른 identity의 결과는 저장 전에 거부한다.
- 이력 저장이나 완료 기록에 실패해도 이미 받은 보고서는 호출자에게 돌려준다. durable completion을 확인한 것으로 표시하지 않는다.
- `gcr requests`로 이 profile/worktree의 기록을 조회한다. `gcr review --retry-finished`는 저장된 terminal 결과를 명시적으로 다시 실행한다. 동시에 들어온 같은 재실행 요청은 한 세대로 합친다.

저장소는 기본 local data directory 아래 `review-requests`에 둔다. Profile별 OS credential과 암호화/CAS 파일 저장 방식을 재사용한다. Trigger별 최소 간격과 시간당 리뷰 시작 예약을 기록하는 core API도 추가했다. 예약은 모델 API 호출 횟수나 실제 token 사용량이 아니다. 현재 범위는 한 profile/worktree이며 사용자 전체 예산은 아직 없다.

## 확인한 범위

GCR client-contract/core/executors/CLI 회귀 검사: 20개 파일, 349 passed, 1 skipped. Skip은 명시적으로 실행하는 실제 계정 smoke다. 실행 기록 전용 10개 검사에는 별도 Node 프로세스의 강제 종료, 두 프로세스의 사유 병합, 오래된 소유권 거부, 동시 요청과 명시적 재실행 병합, 대기자 취소, 저장 실패, authorization 재검사가 포함된다. 모델 응답은 모의 executor로 검증했다.

Client 라이브러리 `0.1.0-alpha.18`, CLI `0.1.0-alpha.12`를 배포용 tarball로 만들고 독립된 consumer에 설치해 import/CLI 진입점을 확인했다. 공개 registry 발행이나 사용자 CLI 교체는 하지 않았다.

## 남은 구현

P07 전체 완료가 아니다. Durable 기록은 고정된 source를 준비한 살아 있는 호출자 사이에서 실행권을 조정한다. 준비된 source payload를 보관해 headless 서비스가 독립 실행·복구하는 기능은 아직 없다. `interrupted` 요청의 결과 대조·명시적 복구 UI, 이력 retention 후 결과가 사라진 요청의 처리, 실행 기록 보존 정책도 남아 있다.

Save·Stage 이벤트 연결, 네 toggle과 repo override, debounce·우선순위·latest generation·전체 사용자 예산, headless IPC/service, 정확한 commit/push 범위, 비파괴 hook 연동과 실제 trigger별 모델 검증을 계속 구현해야 한다. 기존 Stage watcher는 아직 이 공통 실행 서비스로 교체하지 않았다.

## 확장 설치와 실제 계정 검증

Commit Defender `504b87c`에 같은 실행 서비스를 연결했다. 확장 회귀 검사 145개와 source/test TypeScript 검사가 통과했다. 최종 VSIX를 VS Code 1.90.2·1.137.0에서 활성화했고 사용자 설치도 백업 후 갱신했다. 설치된 세 bundle은 최종 VSIX와 byte 단위로 일치한다. 사용자 창의 재시작은 강제하지 않았다.

최종 패키지의 실제 `gpt-6-astra / xhigh` 리뷰는 TypeScript 결함에서 completed 보고서와 finding 1개를 생성했다. 새 worker와 독립 consumer에 설치한 CLI가 같은 보고서를 재사용했고 실행 기록은 한 세대로 유지됐다. 최종 checkpoint의 모델 리뷰는 한 번이며 취소 처리 수정 전 checkpoint까지 합하면 총 두 번이다. 테스트 profile의 OS key와 로컬 기록을 제거했다. 이 검증은 수동 고정 입력의 공유 실행이며 Save·Stage·Commit·Push trigger 검증을 대신하지 않는다.

## Save·Stage 공통 scheduler와 source 관측

`AutomaticReviewScheduler`에 3초 debounce, worktree별 최신 요청 교체, 늦은 완료 차단, 대기 Stage 우선 처리, 수동 실행 중 대기, durable 예산의 `retryAt` 재예약을 구현했다. 저장소 관측은 linked worktree의 실제 index 경로를 찾고 HEAD·index가 관측 중 바뀌면 요청을 거부한다. Save 관측은 경로·ignore·symlink 검사를 거친 저장 바이트를 해시하고 HEAD 대비 working-tree 변경 여부를 계산한다. Index만 다르고 저장 파일은 HEAD로 되돌아간 경우는 Save 변경으로 보지 않는다.

공통 client/CLI 회귀 검사는 22개 파일에서 357 passed, 1 skipped다. Skip은 명시적으로 실행하는 실제 계정 검사다. 새 scheduler 4개와 Git source 관측 4개 검사는 모의 시계 및 임시 실제 Git 저장소를 사용했다. Client 라이브러리 alpha.19와 CLI alpha.13은 별도 버전으로 패키징한다.

이 checkpoint는 core 구현과 회귀 검사까지다. 확장에 이벤트를 연결한 패키지의 실제 Save·Stage 검증은 별도로 기록한다. 부분 hunk unstage 판별, 종료된 host의 누락 이벤트 복구, headless 서비스, Commit·Push 및 사용자 전체 예산은 계속 미완료다.

## 최종 VSIX의 Save·Stage 실검증과 설치

확장 전체 회귀 검사 154개와 source/test TypeScript 검사가 통과했다. 최종 VSIX를 격리된 VS Code 1.137.0에 로드하고 `TextDocument.save()`와 실제 `git add` 이벤트로 각각 `gpt-6-astra / xhigh` 리뷰를 수행했다. 설정은 `Commit Defender: Automatic Reviews`에서 저장소/worktree를 선택해 Save·Stage를 각각 켠다. 신규 설정은 모두 off다. 상세 증거와 남은 범위는 `evidence/P07-automatic.json`에 기록했다.

## Commit index와 Push ref의 고정 source 처리

`commit-tree` source 계약과 snapshot capture를 추가했다. Source/base는 전체 commit OID를 명시하며 현재 HEAD·index로 대체하지 않는다. Force update도 전달된 두 tree를 직접 비교한다. Target branch는 명시한 ref에서만 얻고, base/source tree의 `.gitignore`와 현재 checkout의 제외 규칙을 적용한다. 현재 index가 손상돼도 commit tree 읽기는 index를 사용하지 않는다.

`resolvePrePush`는 stdin 전체를 먼저 검증하고 ref별 ready/ref-deleted/unchanged/unsupported 상태를 보존한다. 64개 ref·256 KiB 한도를 적용하며 새 ref의 base는 명시적으로 empty tree다. 삭제 ref는 source 리뷰 없이 ref-deleted로 기록한다. Commit tag는 peel하고 missing/noncommit object는 fetch하지 않고 unsupported로 남긴다.

CLI의 `review --trigger commit`은 실제 `GIT_INDEX_FILE` 또는 명시적 `--index-file`을 사용한다. `push-review`는 pre-push stdin의 모든 ref를 순서대로 리뷰하며 일부 실패·unsupported도 출력에 남긴다. 이 단계는 foreground CLI이며 독립 서비스의 비동기 advisory 접수·managed hook 설치는 아직 미완료다. Amend는 변경 전 HEAD 대비 이번 amend의 변경을 리뷰한다. 전체 parent-to-rewritten-commit diff를 추정하지 않는다.

실제 임시 Git hook으로 initial commit, `commit --only`, `--amend --only`의 capture tree가 최종 commit tree와 같음을 확인했고 관련 없는 staged 변경이 보존됐다. Local bare remote로 여러 ref, 신규 branch, force update, 삭제 ref 입력을 확인했다. SHA-256, tag peel, missing object, 저장소 변경·index 손상·tree ignore, CLI 사유 병합과 여러 ref 처리도 회귀 검사에 포함했다.

공통 client/CLI 검사 24개 파일에서 371 passed, 1 skipped다. Skip은 명시적인 실제 계정 검사다. Client alpha.20 / CLI alpha.14 패키지의 실제 계정·확장 호환 검증은 다음 기록에 추가한다.

## 패키지의 실제 Commit·Push 리뷰와 확장 설치

독립 consumer에 설치한 CLI alpha.14와 client alpha.20으로 실제 계정 검증을 수행했다. 임시 저장소에만 foreground advisory 테스트 hook을 두고 `git commit --only`와 local bare remote로의 `git push`를 실행했다. 각각 `gpt-6-astra / xhigh` completed 보고서와 finding 1개를 만들었다. Commit 보고서는 실제 최종 commit tree와 같았고 관련 없는 staged 변경이 보존됐다. Push 보고서는 stdin의 이전·새 commit을 고정했으며 실제 remote ref 갱신도 확인했다. 요청 두 개는 각각 generation 1·finished 상태였다.

각 모델 리뷰는 source-read 7건을 기록했고 `sum.ts`, `caller.ts`, `sum.test.ts`, `package.json`의 고정된 source/base를 읽었다. 테스트 파일을 읽은 것이며 모델이 테스트 명령을 실행한 것은 아니다. 이 checkpoint의 실제 모델 리뷰는 총 두 번이다. 테스트 profile의 OS key와 암호화 기록을 제거했다. Foreground 테스트 hook의 Git 종료 정책을 확인한 것이며 독립 서비스·기본 비동기 동작을 검증한 것은 아니다.
