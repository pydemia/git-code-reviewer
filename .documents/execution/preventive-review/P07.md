# P07 실행 기록

## 공통 실행 소유권과 저장된 결과 재사용

CLI의 수동 리뷰를 암호화한 실행 기록에 연결했다. 같은 profile·repository·worktree 안에서 source/base/context/knowledge/review profile/executor/model/tool 설정이 같으면 사유를 합치고 한 프로세스에만 실행권을 준다. 중앙 동기화의 `lastSynchronizedAt`은 내용 변경이 아니므로 중복 판단에서 제외한다. 실행 모드·fallback 사유·중앙 audience·connection은 유지한다.

- `queued → claimed → running → finished`를 CAS로 기록한다. 기본 lease는 30초, 실행 중 갱신은 10초다.
- 실행 전 `claimed` 상태에서 종료된 프로세스는 lease 만료 후 교체할 수 있다. `running` 상태의 lease가 만료되면 `interrupted`로 남긴다. 프로세스 종료만으로 모델 작업의 종료를 단정하거나 재호출하지 않는다.
- 대기하는 호출자를 취소해도 실행 소유자의 작업은 취소하지 않는다.
- 저장된 결과를 재사용할 때도 현재 중앙 접근 권한과 snapshot 상태를 확인한다. 다른 identity의 결과는 저장 전에 거부한다.
- 이력 저장이나 완료 기록에 실패해도 이미 받은 보고서는 호출자에게 돌려준다. durable completion을 확인한 것으로 표시하지 않는다.
- `gcr requests`로 이 profile/worktree의 기록을 조회한다. `gcr review --retry-finished`는 저장된 terminal 결과를 명시적으로 다시 실행한다. 동시에 들어온 같은 재실행 요청은 한 세대로 합친다.

저장소는 기본 local data directory 아래 `review-requests`에 둔다. Profile별 OS credential과 암호화/CAS 파일 저장 방식을 재사용한다. Trigger별 최소 간격과 시간당 리뷰 시작 예약을 기록하는 core API도 추가했다. 예약은 모델 API 호출 횟수나 실제 token 사용량이 아니다. 현재 범위는 한 profile/worktree이며 사용자 전체 예산은 아직 없다.

## 확인한 범위

GCR client-contract/core/executors/CLI 회귀 검사: 20개 파일, 349 passed, 1 skipped. Skip은 명시적으로 실행하는 실제 계정 smoke다. 실행 기록 전용 10개 검사에는 별도 Node 프로세스의 강제 종료, 두 프로세스의 사유 병합, 오래된 소유권 거부, 동시 요청과 명시적 재실행 병합, 대기자 취소, 저장 실패, authorization 재검사가 포함된다. 모델 응답은 모의 executor로 검증했다.

Client 라이브러리 `0.1.0-alpha.18`, CLI `0.1.0-alpha.12`를 배포용 tarball로 만들고 독립된 consumer에 설치해 import/CLI 진입점을 확인했다. 공개 registry 발행이나 사용자 CLI 교체는 하지 않았다.

## 남은 구현

P07 전체 완료가 아니다. Durable 기록은 고정된 source를 준비한 살아 있는 호출자 사이에서 실행권을 조정한다. 준비된 source payload를 보관해 headless 서비스가 독립 실행·복구하는 기능은 아직 없다. `interrupted` 요청의 결과 대조·명시적 복구 UI, 이력 retention 후 결과가 사라진 요청의 처리, 실행 기록 보존 정책도 남아 있다.

Save·Stage 이벤트 연결, 네 toggle과 repo override, debounce·우선순위·latest generation·전체 사용자 예산, headless IPC/service, 정확한 commit/push 범위, 비파괴 hook 연동과 실제 trigger별 모델 검증을 계속 구현해야 한다. 기존 Stage watcher는 아직 이 공통 실행 서비스로 교체하지 않았다.
