# P10 실행 기록

## 승인된 소스 전송 계약과 모델 호출 권한

첫 변경에서는 P10-C01의 계약·검증·키 권한 부분을 구현했다. 아래 API 체크포인트에서 접수·조회·취소와 durable job 저장을 추가했다. 중앙 실행 worker와 client executor는 아직 연결하지 않았으며 P10 전체는 미완료다.

`client-contract`의 `remoteReviewPayload`는 중앙 executor를 별도로 명시한다. Knowledge mode가 standalone이어도 중앙 모델을 선택할 수 있으며 centralized mode에서는 기존 audience와 중앙 모델 audience가 일치해야 한다. 모델 계정 ID·모델명·reasoning effort, 호출/시간/소스 읽기/도구/출력 token 예산, 소스·결과 보존 기간을 요청에 고정한다. 소스는 `client-captured`, 컨텍스트는 `client-supplied`로 표시하며 PR snapshot이나 서버가 승인한 정책으로 취급하지 않는다.

`prepareRemoteReview`는 캡처한 source와 정확한 file/side 목록에서 전송 제안과 SHA-256을 만든다. Diff 원문·branch명·remote·로컬 경로·제외 파일 이름은 보내지 않는다. 선택한 리뷰 파일을 누락하면 준비에 실패하며 관련 파일은 전달한 목록에 있어야 포함한다. 제안을 만들었다고 승인한 것으로 처리하지 않는다. Host가 별도로 받은 승인에는 전체 payload hash와 시각이 필요하다. 요청 ID·audience·계정·모델·예산·보존 기간·파일·컨텍스트가 바뀌면 기존 승인과 일치하지 않는다.

서버에서도 사용할 `validateRemoteReviewRequest`는 payload 최대 8 MiB, 파일 최대 512개/각 2 MiB, 경로 제외 정책, UTF-8 바이트·줄 수·SHA-256·Git blob OID, 선택 파일 존재, 컨텍스트 본문 hash, 인증된 audience/clientId를 확인한다. 원래 snapshot hash는 클라이언트의 캡처 식별자이며 서버가 Git tree 전체를 검증한 증거가 아니다. 업로드한 파일·컨텍스트 전체의 일치는 별도 payload hash로 검사한다. 승인 시각의 5분 유효성은 신규 접수에만 적용하도록 분리했다. 오래된 동일 요청의 receipt 조회까지 차단해서 새 모델 호출을 유발하면 안 된다.

Job status/cancel/result의 decoder를 정의했다. 실행 상태를 알 수 없는 `uncertain`과 취소 요청·취소 완료를 구분한다. 결과 hash와 응답의 실제 대조, lost-ack 처리, idempotent receipt 저장, 소스·결과의 실제 정리는 후속 구현에 남아 있다. 계약에 보존 기간이 있다는 사실을 삭제 동작의 검증으로 해석하지 않는다.

Migration 0046은 명시적인 `ai:invoke` scope를 추가하며 기존 키의 scope는 변경하지 않는다. 이 scope의 발급과 사용에는 현재 저장소 reviewer/administrator grant가 필요하다. 직접 grant 또는 현재 그룹 grant를 평가하고 사용자·tenant·저장소 비활성화, 삭제, 키 폐기·기존 identity 검사를 유지한다. 모델 경로의 native bearer 요청에만 origin 없는 POST를 허용하며 명시적인 외부 origin과 잘못된 bearer는 거부한다. 실제 모델 route에서는 별도로 client principal, 외부 authorization, 계정 grant와 admission을 확인해야 한다. 작업 실행이 준비되기 전이므로 공개 auth config나 키 발급 UI에서 중앙 실행 기능을 광고하지 않는다.

## 검증과 배포 상태

- 소스 전송 검사 34개 통과: 실제 Git index 캡처, 승인하지 않은 관련/제외 파일 누출 방지, 캡처 뒤 편집, SHA-1/SHA-256 blob, 잘못된 경로·바이트·승인·audience·컨텍스트·크기·예산 검사.
- PostgreSQL 통합 검사 15개 통과: migration 0046 적용, 조회 전용 키 거부, 명시적 scope와 저장소 grant, 발급 뒤 viewer로 변경, 그룹 권한 변경, 키 폐기, 기존 기준 조회·결과/피드백 제출 회귀 검사. 모델 호출은 fixture의 admission 응답으로 검사했으며 실제 모델 호출은 0회다.
- Docker의 기존 pinned PostgreSQL 이미지 읽기가 daemon content store I/O 오류로 실패했다. 저장소의 `with-native-test-postgres.mjs`로 PostgreSQL 18.3 임시 DB를 실행했으며 종료와 디렉터리 정리를 확인했다. 이 결과는 컨테이너·배포·DB TLS 검증을 대신하지 않는다.

Client 계약/core 및 runtime source와 변경한 테스트의 타입 검사와 변경 파일 lint도 통과했다. 이 변경은 아직 패키지 릴리스·VSIX 설치·PRISM Helm 배포 대상이 아니다. 기존 Commit Defender 2.8.1과 PRISM 서비스는 유지한다. 다음 작업은 이 계약을 받는 repository별 API, idempotent job 저장·조회·취소와 중앙 계정 admission/worker 연결이다. P00–P13 전체 goal과 앞선 phase의 잔여 범위를 유지한다.

검증 hash와 환경 기록은 [P10-authorized-transfer.json](evidence/P10-authorized-transfer.json)에 보관한다.

## Repository API와 durable job 접수

앞선 계약에 `POST remote-reviews`, request ID 기반 status/result 조회와 cancel API를 연결했다. Migration 0047은 기존 PR snapshot과 별개로 암호화된 source·result, 승인 hash, 최초 key와 계정, 예산 예약, 만료 시각, 상태를 저장한다. Runtime에 client-core dependency와 최종 이미지 COPY 경로를 추가해 클라이언트와 같은 업로드 validator를 사용한다.

같은 server·tenant·repository·user·client·request ID에 대해 최초 접수만 작업과 예산 예약을 만든다. 입력이 다르면 409이며 키 교체·재전송·오래된 승인 시각은 기존 작업을 새로 실행하지 않는다. Serializable transaction에서 실제 key와 현재 repo/외부 인가를 재확인하고 기존 account registry의 현재 모델 할당을 검사한다. 사용자·저장소 budget reservation은 각각의 advisory lock으로 직렬화한다.

Queued 취소는 소스 ciphertext·IV·tag를 지우고 cancelled로 기록한다. Running 취소는 cancel-requested이며 provider 종료를 단정하지 않는다. 보존 만료 후에도 receipt는 남긴다. 소스 만료 시 queued는 expired, running/cancel-requested는 uncertain으로 전환한다. 결과 만료는 암호화 결과를 제거한다. 정리 함수는 worker 복구 주기와 retention 명령, 개별 조회에 연결했다. 실제 worker의 실행·취소와 checkpoint는 P10-C02에 남아 있다.

이번 검증은 52개 통과했다. 신규 작업 API 16개, 기존 scoped key/제출 회귀 15개, config 검사 21개다. 실제 loopback HTTP 요청을 server commit 후 receipt 전송 전에 끊고 status 조회와 동일 요청 재전송으로 작업 1개와 모델 호출 상한 2회에 대한 예약 1건이 유지되는 것을 확인했다. 키 교체 후 조회, 동시 재전송, read-only/다른 사용자/다른 저장소 거부, 초기 HTTP 인증 뒤 key 폐기, 외부 인가 실패, 계정 할당 변경, cross-user/repository 예산, 취소·소스/결과 만료와 result 변조도 확인했다. 결과 응답 검사는 암호화된 합성 report를 사용했으며 실제 모델 호출은 0회다.

Runtime build, 변경한 source/test 타입 검사와 lint를 통과했다. PostgreSQL 18.3 임시 DB에서 migration 0047을 적용하고 검증 후 종료·삭제를 확인했다. Docker I/O 장애는 해결한 것으로 처리하지 않으며 이미지 빌드·Helm 배포 검증을 주장하지 않는다.

`REMOTE_REVIEWS_ENABLED`는 기본 false다. Registry 암호화·scoped client auth·model admission이 없으면 설정을 거부한다. API와 보존 처리는 구현됐지만 중앙 실행 worker와 CD/CLI remote executor는 아직 연결하지 않았으므로 운영 활성화와 배포는 진행하지 않았다. [운영 계약](../../../docs/operations/remote-review-jobs.md)과 [검증 기록](evidence/P10-job-admission.json)에 범위를 남긴다. 다음 작업은 승인된 job의 실행 소유권, 최초 key의 유효성 및 계정 할당 재검증, 공통 source tool을 사용한 중앙 모델 리뷰다.

## Provider 전송 기록과 registered model 어댑터

P10-C02의 실행 소유권과 모델 어댑터를 구현했다. Migration 0048에 실제 provider 요청 전 기록과 다음 대기 시각을 추가했다. Claim은 실행별 owner와 30초 lease를 만들며 최초 key·현재 repository/외부 인가·계정 모델 할당을 재검증한다. Bearer token은 worker에 복사하지 않는다. Key를 교체해 조회할 수 있어도, 이미 접수한 작업의 최초 key가 폐기되면 실행 권한은 사라진다.

기존 model admission에 `beforeSend`를 추가했다. 슬롯이 없어 대기할 때는 invocation 기록이 없고, 슬롯 확보 뒤 전송 직전에 owner·현재 인가를 대조하고 기록한다. 그 뒤 lease를 잃으면 uncertain이며 자동 재실행하지 않는다. 전송 전 owner만 queued로 되돌리거나 next-attempt 시각을 지정할 수 있다. 실제 worker 복구 주기에 이 lease 복구를 연결했다.

완료 report는 승인된 client/source/model/account 설정과 파일 범위를 확인해 암호화한다. Report와 완료 receipt를 같은 transaction에서 저장하고 원본 소스를 지운다. 다른 owner, 만료된 lease, 취소 이후 응답은 거부한다. Report 자체의 모델 답변 검증은 공통 review runner가 담당한다.

소스 도구 선언을 client-contract로 옮겨 기존 CLI MCP bridge와 중앙 registered model 어댑터가 같은 선언을 사용하게 했다. 새 어댑터는 등록된 모델의 turn에서 source tool 요청을 처리하고 공통 review runner에 JSON 응답을 반환한다. 실제 Git index 캡처를 읽어 read ID와 coverage가 있는 completed report를 만드는 검사를 통과했다. 모델은 합성 응답을 사용했다.

현재 registered Codex 전송 코드는 출력 token 상한을 강제하지 않으므로 remote 계약의 `outputTokensPerCall`을 선택 항목으로 바꿨다. 지정한 신규 요청은 422로 거부하며 factory도 해당 상한을 무시하지 않는다. 생략 시 호출·시간·source/tool 예산과 별도의 출력 바이트 제한을 사용한다. 이는 token 상한을 검증한 결과가 아니다.

검사 88개가 통과했다. API/실행 소유권 21개, 기존 client credential 15개, model admission 6개, 중앙 executor 8개, source bridge 3개, remote transfer 35개다. 실제 PostgreSQL에서 동시 claim, 용량 대기와 전송 전 인가 거부, 최초 key 폐기, lease 복구와 이전 owner 거부, atomic report 저장, 취소 뒤 완료 거부를 검증했다. 이 checkpoint의 실제 계정 모델 호출은 0회다.

Client package build, runtime build, web 및 변경한 테스트 타입 검사, 변경 파일 lint가 통과했다. 실행 소유권 함수와 registered model 어댑터는 검증했지만 queued upload부터 실제 모델까지 연결한 worker 루프는 아직 없다. 업로드한 변경 종류·rename/base와 승인된 context를 공통 source/context로 복원하고 중앙 knowledge pin을 유지하는 경로를 먼저 연결해야 한다. 이어서 실제 계정·취소·배포를 검증한다. P10-C02와 전체 goal은 미완료이며 기본 비활성 설정을 유지한다. 증거는 [P10-execution-foundation.json](evidence/P10-execution-foundation.json)에 기록한다.
