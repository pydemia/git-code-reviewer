# P10 실행 기록

## 계정·모델 조회와 client capability — 2026-09-15

Repository별 중앙 모델 목록 API를 추가했다. 실제 client key의 `ai:invoke`, repository 접근과 등록 계정 할당을 다시 확인하며 credential 복호화·모델 호출·예산 예약 없이 허용된 모델과 effort, 실행 상한만 반환한다. SDK와 CLI `remote-review models`도 같은 인가·audience 계약을 사용한다. 서버 프로필의 key 생성 화면은 중앙 실행이 활성화된 경우에만 별도의 미선택 권한 checkbox를 표시한다.

확장 연동 중 `ai:invoke`가 포함된 정상 identity 응답을 client decoder가 거부하는 결함을 수정했다. 실제 API key 응답과 CLI HTTPS fixture에서 이 권한을 포함한 연결을 검증했다. Client package alpha.33과 CLI alpha.29를 만들었으며 clean consumer import와 독립 CLI 설치가 통과했다. [검증 기록](evidence/P10-model-discovery.json)에 package hash와 검사 범위를 기록한다. 반복한 검사와 제외한 검사를 신규 완료 건수에 합산하지 않는다.

CD 모델 선택·전송 승인·복구 UI는 별도 worktree에서 연결 중이다. 실제 계정 모델 호출, VSIX 전달, Docker 저장소 오류 해결과 PRISM 배포는 이 checkpoint의 완료 범위에 포함하지 않는다. P10과 전체 goal은 계속 진행 중이다.

## Client 복구·전송과 CLI 중앙 실행 — 2026-09-14

공통 client에 제출 전 암호화된 요청 기록, 명시적 재전송, 상태 조회·대기·취소·결과 확인을 연결했다. 기록은 요청 ID·승인 hash·결과 대조용 metadata만 보관하며 source/knowledge/report 본문은 넣지 않는다. 같은 ID로 submit하면 조회만 하며 404·통신 실패·재시작이 새 요청을 허용하지 않는다. Retry는 동일 payload와 최초 승인 시각을 유지하고 취소 요청 이후에는 차단한다. 결과의 client/source/context·계정/모델/effort/호출 상한·전송 파일 범위·report hash와 receipt 보존 시각을 대조한다. 중앙 read receipt를 로컬 읽기 근거로 변환하지 않는다.

CLI의 `remote-review preview|submit|retry|status|wait|result|cancel|list`를 추가했다. 로컬 지식과 중앙 실행을 함께 선택할 수 있고 중앙 지식을 선택하면 승인된 manifest pin을 유지한다. 미리보기는 실제 전송 자료와 예산·보존 기간을 출력하며 제출에는 정확한 payload hash 확인을 요구한다. 기존 로컬 executor는 호출하지 않는다. 계정 ID는 명시적으로 받아 기존 서버 registry에서 인가한다. 가용 계정/모델 선택 UI나 실제 계정 사용 가능 확인을 구현했다고 표시하지 않는다.

실제 client HTTP를 worker 통합 검사에 연결하면서 동시 DB transaction의 상태 조회가 409로 충돌하는 경우를 확인했다. 제한 시간 안에서 동일 ID의 GET만 재시도하는 wait를 추가했다. 인가 실패와 응답 불일치는 재시도하지 않으며 timeout이나 로컬 취소를 서버 취소 완료로 표시하지 않는다. 보완 후 실제 HTTP 접수→worker→합성 등록 계정의 두 model turn→암호화 report→client 결과 대조가 통과했다.

클라이언트 회귀 116개(1개 제외), 추가 대기 시나리오 2개, 서버 회귀 46개가 통과했다. 마지막 targeted 실행은 client/대기 21개, CLI 명령 2개, 실제 client HTTP와 worker 연결 1개이며 앞선 검사와 중복된다. 제외한 검사를 완료 건수에 더하지 않는다. PostgreSQL 18.3 임시 DB 정리를 확인했고 client/CLI/runtime build, 변경 테스트 타입 검사와 lint가 통과했다. 실제 사용자 계정 모델 호출은 0회다. [검증 기록](evidence/P10-client-execution.json)에 파일 hash와 로그를 보관한다.

패키지 버전·설치본과 PRISM 배포는 바꾸지 않았다. Docker 저장소 I/O 복구와 이미지 빌드, CD 승인·진행 UI, 계정/모델 조회와 client capability, 패키지 전달, 실제 계정 검증이 남아 있다. P10과 전체 goal은 미완료다. 아래 기록은 이전 checkpoint의 당시 상태다.

## 승인된 소스 전송 계약과 모델 호출 권한

첫 변경에서는 P10-C01의 계약·검증·키 권한 부분을 구현했다. 아래 API 체크포인트에서 접수·조회·취소와 durable job 저장을 추가했다. 중앙 실행 worker와 client executor는 아직 연결하지 않았으며 P10 전체는 미완료다.

`client-contract`의 `remoteReviewPayload`는 중앙 executor를 별도로 명시한다. Knowledge mode가 standalone이어도 중앙 모델을 선택할 수 있으며 centralized mode에서는 기존 audience와 중앙 모델 audience가 일치해야 한다. 모델 계정 ID·모델명·reasoning effort, 호출/시간/소스 읽기/도구/출력 token 예산, 소스·결과 보존 기간을 요청에 고정한다. 소스는 `client-captured`, 컨텍스트는 `client-supplied`로 표시하며 PR snapshot이나 서버가 승인한 정책으로 취급하지 않는다.

`prepareRemoteReview`는 캡처한 source와 정확한 file/side 목록에서 전송 제안과 SHA-256을 만든다. Diff 원문·branch명·remote·로컬 경로·제외 파일 이름은 보내지 않는다. 선택한 리뷰 파일을 누락하면 준비에 실패하며 관련 파일은 전달한 목록에 있어야 포함한다. 제안을 만들었다고 승인한 것으로 처리하지 않는다. Host가 별도로 받은 승인에는 전체 payload hash와 시각이 필요하다. 요청 ID·audience·계정·모델·예산·보존 기간·파일·컨텍스트가 바뀌면 기존 승인과 일치하지 않는다.

서버에서도 사용할 `validateRemoteReviewRequest`는 payload 최대 8 MiB, 파일 최대 512개/각 2 MiB, 경로 제외 정책, UTF-8 바이트·줄 수·SHA-256·Git blob OID, 선택 파일 존재, 컨텍스트 본문 hash, 인증된 audience/clientId를 확인한다. 원래 snapshot hash는 클라이언트의 캡처 식별자이며 서버가 Git tree 전체를 검증한 증거가 아니다. 업로드한 파일·컨텍스트 전체의 일치는 별도 payload hash로 검사한다. 승인 시각의 5분 유효성은 신규 접수에만 적용하도록 분리했다. 오래된 동일 요청의 receipt 조회까지 차단해서 새 모델 호출을 유발하면 안 된다.

Job status/cancel/result의 decoder를 정의했다. 실행 상태를 알 수 없는 `uncertain`과 취소 요청·취소 완료를 구분한다. 결과 hash와 응답의 실제 대조, lost-ack 처리, idempotent receipt 저장, 소스·결과의 실제 정리는 후속 구현에 남아 있다. 계약에 보존 기간이 있다는 사실을 삭제 동작의 검증으로 해석하지 않는다.

Migration 0046은 명시적인 `ai:invoke` scope를 추가하며 기존 키의 scope는 변경하지 않는다. 이 scope의 발급과 사용에는 현재 저장소 reviewer/administrator grant가 필요하다. 직접 grant 또는 현재 그룹 grant를 평가하고 사용자·tenant·저장소 비활성화, 삭제, 키 폐기·기존 identity 검사를 유지한다. 모델 경로의 native bearer 요청에만 origin 없는 POST를 허용하며 명시적인 외부 origin과 잘못된 bearer는 거부한다. 실제 모델 route에서는 별도로 client principal, 외부 authorization, 계정 grant와 admission을 확인해야 한다. 작업 실행이 준비되기 전이므로 공개 auth config나 키 발급 UI에서 중앙 실행 기능을 광고하지 않는다.

## 검증과 배포 상태

- 소스 전송 검사 34개 통과: 실제 Git index 캡처, 승인하지 않은 관련/제외 파일 누출 방지, 캡처 뒤 편집, SHA-1/SHA-256 blob, 잘못된 경로·바이트·승인·audience·컨텍스트·크기·예산 검사.
- PostgreSQL 통합 검사 15개 통과: migration 0046 적용, 조회 전용 키 거부, 명시적 scope와 저장소 grant, 발급 뒤 viewer로 변경, 그룹 권한 변경, 키 폐기, 기존 기준 조회·결과/피드백 제출 회귀 검사. 모델 호출은 fixture의 admission 응답으로 검사했으며 실제 모델 호출은 0회다.
- Docker의 기존 pinned PostgreSQL 이미지 읽기가 daemon content store I/O 오류로 실패했다. 저장소의 `with-native-test-postgres.mjs`로 PostgreSQL 18.3 임시 DB를 실행했으며 종료와 디렉터리 정리를 확인했다. 이 결과는 컨테이너·배포·DB TLS 검증을 대신하지 않는다.

Client 계약/core 및 runtime source와 변경한 테스트의 타입 검사와 변경 파일 lint도 통과했다. 이 변경은 아직 패키지 릴리스·VSIX 설치·PRISM Helm 배포 대상이 아니다. 기존 Commit Defender 2.8.1과 PRISM 서비스는 유지한다. 다음 작업은 이 계약을 받는 repository별 API, idempotent job 저장·조회·취소와 중앙 계정 admission/worker 연결이다. P00–P13 전체 goal과 앞선 phase의 잔여 범위를 유지한다.

검증 hash와 환경 기록은 [P10-authorized-transfer.json](evidence/P10-authorized-transfer.json)에 보관한다.

## Repository API와 durable job 접수

앞선 계약에 `POST remote-reviews`, request ID 기반 status/result 조회와 cancel API를 연결했다. Migration 0047은 기존 PR snapshot과 별개로 암호화된 source·result, 승인 hash, 최초 key와 계정, 예산 예약, 만료 시각, 상태를 저장한다. Runtime에 client-core dependency와 최종 이미지 COPY 경로를 추가해 클라이언트와 같은 업로드 validator를 사용한다.

같은 server·tenant·repository·user·client·request ID에 대해 최초 접수만 작업과 예산 예약을 만든다. 입력이 다르면 409이며 키 교체·재전송·오래된 승인 시각은 기존 작업을 새로 실행하지 않는다. Serializable transaction에서 실제 key와 현재 repo/외부 인가를 재확인하고 기존 account registry의 현재 모델 할당을 검사한다. 사용자·저장소 budget reservation은 각각의 advisory lock으로 직렬화한다.

Queued 취소는 소스 ciphertext·IV·tag를 지우고 cancelled로 기록한다. Running 취소는 cancel-requested이며 provider 종료를 단정하지 않는다. 보존 만료 후에도 receipt는 남긴다. 소스 만료 시 queued는 expired, running/cancel-requested는 uncertain으로 전환한다. 결과 만료는 암호화 결과를 제거한다. 정리 함수는 worker 복구 주기와 retention 명령, 개별 조회에 연결했다. 실제 worker의 실행·취소와 checkpoint는 P10-C02에 남아 있다.

이번 검증은 52개 통과했다. 신규 작업 API 16개, 기존 scoped key/제출 회귀 15개, config 검사 21개다. 실제 loopback HTTP 요청을 server commit 후 receipt 전송 전에 끊고 status 조회와 동일 요청 재전송으로 작업 1개와 모델 호출 상한 2회에 대한 예약 1건이 유지되는 것을 확인했다. 키 교체 후 조회, 동시 재전송, read-only/다른 사용자/다른 저장소 거부, 초기 HTTP 인증 뒤 key 폐기, 외부 인가 실패, 계정 할당 변경, cross-user/repository 예산, 취소·소스/결과 만료와 result 변조도 확인했다. 결과 응답 검사는 암호화된 합성 report를 사용했으며 실제 모델 호출은 0회다.

Runtime build, 변경한 source/test 타입 검사와 lint를 통과했다. PostgreSQL 18.3 임시 DB에서 migration 0047을 적용하고 검증 후 종료·삭제를 확인했다. Docker I/O 장애는 해결한 것으로 처리하지 않으며 이미지 빌드·Helm 배포 검증을 주장하지 않는다.

`REMOTE_REVIEWS_ENABLED`는 기본 false다. Registry 암호화·scoped client auth·model admission이 없으면 설정을 거부한다. API와 보존 처리는 구현됐지만 중앙 실행 worker와 CD/CLI remote executor는 아직 연결하지 않았으므로 운영 활성화와 배포는 진행하지 않았다. [운영 계약](../../../docs/operations/remote-review-jobs.md)과 [검증 기록](evidence/P10-job-admission.json)에 범위를 남긴다. 다음 작업은 승인된 job의 실행 소유권, 최초 key의 유효성 및 계정 할당 재검증, 공통 source tool을 사용한 중앙 모델 리뷰다.

## Provider 전송 기록과 registered model 어댑터

P10-C02의 실행 소유권과 모델 어댑터를 구현했다. Migration 0048에 실제 provider 요청 전 기록과 다음 대기 시각을 추가했다. Claim은 실행별 owner와 30초 lease를 만들며 최초 key·현재 repository/외부 인가·계정 모델 할당을 재검증한다. Bearer token은 worker에 복사하지 않는다. Key를 교체해 조회할 수 있어도, 이미 접수한 작업의 최초 key가 폐기되면 실행 권한은 사라진다.

기존 model admission에 `beforeSend`를 추가했다. 슬롯이 없어 대기할 때는 invocation 기록이 없고, 슬롯 확보 뒤 전송 직전에 owner·현재 인가를 대조하고 기록한다. 그 뒤 lease를 잃으면 uncertain이며 자동 재실행하지 않는다. 전송 전 owner만 queued로 되돌리거나 next-attempt 시각을 지정할 수 있다. 실제 worker 복구 주기에 이 lease 복구를 연결했다.

완료 report는 승인된 client/source/model/account 설정과 파일 범위를 확인해 암호화한다. Report와 완료 receipt를 같은 transaction에서 저장하고 원본 소스를 지운다. 다른 owner, 만료된 lease, 취소 이후 응답은 거부한다. Report 자체의 모델 답변 검증은 공통 review runner가 담당한다.

소스 도구 선언을 client-contract로 옮겨 기존 CLI MCP bridge와 중앙 registered model 어댑터가 같은 선언을 사용하게 했다. 새 어댑터는 등록된 모델의 turn에서 source tool 요청을 처리하고 공통 review runner에 JSON 응답을 반환한다. 실제 Git index 캡처를 읽어 read ID와 coverage가 있는 completed report를 만드는 검사를 통과했다. 모델은 합성 응답을 사용했다.

현재 registered Codex 전송 코드는 출력 token 상한을 강제하지 않으므로 remote 계약의 `outputTokensPerCall`을 선택 항목으로 바꿨다. 지정한 신규 요청은 422로 거부하며 factory도 해당 상한을 무시하지 않는다. 생략 시 호출·시간·source/tool 예산과 별도의 출력 바이트 제한을 사용한다. 이는 token 상한을 검증한 결과가 아니다.

검사 88개가 통과했다. API/실행 소유권 21개, 기존 client credential 15개, model admission 6개, 중앙 executor 8개, source bridge 3개, remote transfer 35개다. 실제 PostgreSQL에서 동시 claim, 용량 대기와 전송 전 인가 거부, 최초 key 폐기, lease 복구와 이전 owner 거부, atomic report 저장, 취소 뒤 완료 거부를 검증했다. 이 checkpoint의 실제 계정 모델 호출은 0회다.

Client package build, runtime build, web 및 변경한 테스트 타입 검사, 변경 파일 lint가 통과했다. 실행 소유권 함수와 registered model 어댑터는 검증했지만 queued upload부터 실제 모델까지 연결한 worker 루프는 아직 없다. 업로드한 변경 종류·rename/base와 승인된 context를 공통 source/context로 복원하고 중앙 knowledge pin을 유지하는 경로를 먼저 연결해야 한다. 이어서 실제 계정·취소·배포를 검증한다. P10-C02와 전체 goal은 미완료이며 기본 비활성 설정을 유지한다. 증거는 [P10-execution-foundation.json](evidence/P10-execution-foundation.json)에 기록한다.


## 업로드된 소스와 공통 리뷰 실행기 연결

`ReviewSourceView`를 도입해 공통 context·policy·source tool·runner가 로컬 캡처와 승인된 업로드를 모두 읽도록 했다. 로컬 캡처의 저장·복원 형식은 유지하고 줄 범위 처리만 같은 함수로 공유한다. Remote view는 전송한 바이트만 보유하며 checkout이나 Git object를 만들어 원본 캡처라고 주장하지 않는다.

전송 제안에 선택 파일의 변경 종류·rename 이전 경로·기준 파일 상태를 추가했다. 전체 승인 hash에 포함하며 선택 집합과 실제 업로드된 file/side를 대조한다. 기준 파일이 전송되지 않았으면 absent로 바꾸지 않고 context를 needs-context로 만든다. 기존 payload의 조회·동일 요청 재전송은 유지하되 변경 정보가 없는 신규 접수와 실행 복원은 거부한다. 캡처 실패는 제외 파일 이름 없이 불완전 여부만 보내고 완료 판정에도 반영한다.

실제 임시 Git 저장소에서 추가·수정·삭제·rename을 캡처하고 원본 저장소와 캡처를 제거한 뒤 공통 runner로 completed report를 생성했다. Rename의 기준 파일을 모델이 읽지 않으면 partial이며 업로드 자체에 없으면 모델 실행 전에 중단한다. 중앙 registered model 어댑터도 원본 checkout 제거 후 전송 소스를 읽는 검사를 통과했다. 모델 응답은 합성이며 실제 계정 호출은 0회다. 빈 context fixture는 instructions/memory/skill 또는 중앙 기준 복원이 완료됐다는 증거가 아니다.

관련 고유 검사 176개가 통과했다. 소스·context·runner·중앙 기준·MCP 회귀 146개와 중앙 executor 8개, 작업 API/DB 22개다. 신규 소스 복원 13개는 회귀 146개에 포함하며 마지막 DB/adapter/source 실행 43개에서 다시 검증했다. PostgreSQL 18.3 임시 DB에서 새 변경 정보의 암호화 저장·인가된 복원과 과거 형식 receipt의 재전송 시 중복 예약 방지를 확인했고 DB 정리도 완료했다. Client package/runtime build, 변경 테스트 타입 검사, 변경 파일 lint와 diff 검사가 통과했다.

승인된 context와 중앙 knowledge pin을 복원한 뒤 실제 worker 루프에 claim·heartbeat·인가·model admission·취소·결과 저장을 연결해야 한다. Client remote executor와 선택/승인 UI, 실제 계정 호출, 패키지·VSIX·Helm 배포도 남아 있다. 이번 변경은 소스 커밋이며 PRISM과 설치된 Commit Defender 2.8.1을 변경하지 않았다. P10-C02와 P00–P13 전체 goal은 계속 진행 중이다. [검증 기록](evidence/P10-upload-source.json)에 범위와 결과를 남긴다.


## 승인된 컨텍스트 복원과 중앙 knowledge pin

준비된 context를 전송 제안으로 내보내고 서버에서 공통 리뷰 context로 복원하는 경로를 추가했다. 선택한 local memory/Skill과 추가 문서, 필수 source, built-in 버전, 만료 시각을 유지한다. 원래 context hash를 보존하면서 실제 전송된 context 전체와 client/source 범위로 실행 context hash를 만든다. 이 hash를 report 완료 저장에도 대조한다. 필수 자료가 누락되거나 context 선택이 불완전하면 내보내지 않으며, 복원 시 지식·만료·version 오류를 빈 context로 대체하지 않는다.

Centralized context는 승인된 manifest와 선택 조건·결과 hash를 포함한다. 기존에는 branch를 전송하지 않았지만 branch 조건이 있는 중앙 기준의 동일한 선택을 재현하려면 해당 이름이 필요하므로 명시적인 context 승인 필드에만 포함한다. 일반 source 전송에는 여전히 branch/HEAD를 추가하지 않는다. 서버는 저장된 원래 manifest와 현재 권한·publication을 확인하고 기존 bundle download 서비스에서 해당 pin의 자료만 읽는다. Byte/hash/scope를 확인한 bundle을 공통 선택기에 넣고 승인된 selection hash와 대조한다. 과거 pin이 더 이상 유효하지 않으면 새 manifest나 최신 지식으로 몰래 바꾸지 않는다.

공통 core 검사 145개와 runtime 검사 31개가 통과했다. Runtime은 작업 API 22개, 중앙 adapter 8개, 승인된 pin의 DB/artifact/권한·publication 변경 검사 1개다. Knowledge HTTP suite의 나머지 18개는 이번 targeted 실행에서 제외했으며 완료 검사 수에 포함하지 않는다. Local Skill·추가 지시문이 실제 runner prompt와 완료 report에 유지되고, 중앙 selection을 그대로 복원하며, 실행 중 authority 폐기 시 취소 신호가 전달됨을 확인했다. 원본 checkout 제거 뒤 uploaded source와 복원된 context를 registered model 어댑터에 전달하는 검사도 통과했다. 모델 응답은 합성으로 실제 계정 호출은 0회다.

DB 검사의 최초 두 실패는 새 source/context 결합 조건을 빠뜨린 요청 fixture와 사용자 재활성화 뒤 publication 대기를 생략한 fixture였다. 각각 두 source hash를 함께 바꾸고 publication을 처리한 뒤 다시 검증했다. 확장한 타입 검사에서 기존 fixture의 `bytes` 필드를 `byteLength`로 고치고 HTTP callback 타입을 명시했다. 테스트용 noEmit root 범위도 실제 cross-package import에 맞췄다. 최종 client/runtime build, 변경 테스트 타입 검사와 lint가 통과했다. PostgreSQL 18.3 임시 DB는 정리됐다. 컨테이너·TLS·운영 배포 검증으로 계산하지 않는다.

신규 접수에는 resolved context를 요구하고 과거 형식 receipt의 재전송·조회는 유지한다. 다음 구현은 실제 worker 루프에서 claim·source/context 복원·등록 계정 선택·model admission·heartbeat·취소·결과 저장을 연결하는 작업이다. 자동 실행과 실제 계정 모델 검증, CD/CLI 승인 UI 및 패키지·VSIX·Helm 배포는 아직 남아 있다. P10-C02와 전체 goal은 미완료이며 현재 설치/배포본은 변경하지 않았다. [검증 기록](evidence/P10-approved-context.json)에 범위와 결과를 기록한다.


## Worker 자동 실행과 상태 정리

접수된 작업의 claim부터 source/context 복원, 등록 계정 선택, 공통 리뷰와 model admission, 암호화 결과 저장을 worker에 연결했다. 기존 기준 생성·대화·PR 실행 기회를 유지하면서 전체 concurrency 안에서 중앙 요청을 처리한다. 최초 전송 전 용량 부족은 같은 receipt를 queued로 돌리고 전송 이후에는 전체 작업을 다시 실행하지 않는다. 승인된 실행 시간에는 준비 시간도 포함한다. 2초 주기로 lease·인가·context를 확인하며 전송 직전에 pin과 실행 fence를 대조한다.

실제 로컬 HTTP Responses 서버와 합성 등록 계정을 이용해 runWorker의 전체 경로를 실행했다. 임시 DB API 접수, 별도 worker DB pool의 claim, 실제 registry 복호화·HTTP 전송, tool 요청/응답, report 저장과 결과 조회가 연결됐다. 호출 전 용량 대기와 같은 요청 재개, 실행 중 API 취소와 최초 key 폐기, 중단된 stream, 잘못된 출력, 호출 상한, 호출 전 worker 종료도 확인했다. 정리를 완료하지 않는 모델 dependency를 계측해 timeout 후 5초 정리 대기를 거쳐 uncertain으로 남는지도 검사했다. 정상 HTTP 모델 transport의 동작과 이 비협조 dependency 검사를 구분한다. 실제 사용자 계정 모델 호출은 0회다.

고유 검사 46개가 통과했다. 작업 API/worker 32개, model admission 6개, 중앙 adapter 8개다. Migration 0049는 만료·누락된 승인 context를 모델 출력 오류와 구분하는 context-unavailable 실패 사유를 추가한다. 모델을 읽거나 전송하기 전에 이 사유로 종료하는 것도 확인했다. Runtime build, 변경 테스트 타입 검사, 변경 파일 lint와 diff 검사가 통과했다. PostgreSQL 18.3 임시 DB 정리를 확인했다. Helm 기본/활성 템플릿에서 server·worker의 동일한 활성화·budget·client key·server ID와 중복 env 부재를 확인했고 admission/registry 비활성 및 0 예산 설정을 거부했다. Helm에는 원래 client key 활성화가 knowledge publication/distribution을 요구하는 제약이 있어 해당 전제도 유지한다.

PRISM-DEV를 다시 확인했다. GCR Helm revision 58, chart 0.10.44, app alpha.47의 server 1/1·worker 1/1 deployment, Keycloak 2/2와 PostgreSQL 1/1이 정상이다. Docker daemon 29.3.1 응답을 확인했지만 기존 content-store 오류가 해결됐다고 단정하지 않는다. 이 checkpoint의 기본 중앙 실행 설정은 비활성이다. 이미지 빌드·실제 계정 호출·CD/CLI 연결 및 최종 배포 검증은 이어서 진행한다. P10과 전체 goal은 미완료다. [검증 기록](evidence/P10-worker-execution.json)에 범위를 보관한다.


### Runtime image 빌드 시도

Worker 소스 `42157251baf2b937127694d369e1beb9c53778a2`를 amd64 `0.8.0-alpha.48` 이미지로 빌드하려 했지만 BuildKit이 Docker containerd의 `meta.db` 쓰기에서 input/output error로 종료했다. 빌드 명령은 exit 1로 끝났고 같은 작업을 중복 실행하지 않았다. Docker daemon과 builder 조회는 응답하지만 실제 저장소 쓰기는 정상이라고 볼 수 없다. 호스트 Data 볼륨도 사용률 99%, 여유 7.3 GiB다. 여유 공간과 I/O 오류의 인과관계를 확정한 것은 아니다.

이미지 push와 Helm 변경은 수행하지 않았다. 기존 PRISM revision 58을 유지한다. Docker 저장소 복구 전에도 CD/CLI의 remote executor·승인 UI 구현을 계속할 수 있으므로 전체 goal을 blocked로 바꾸지 않는다. [실패 기록](evidence/P10-runtime-build-attempt.json)에 명령 대상과 오류를 남긴다.
