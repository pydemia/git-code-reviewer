# API key 연결과 복수 저장소 권한 — 2026-09-26

GCR 발급 화면과 CD 연결 흐름을 수정했다. API key는 기존 `knowledge:read` reader credential이며 새 인증 방식이나 테이블은 추가하지 않았다.

## 사용자 동작

GCR의 내 프로필 → 클라이언트 설정에서 Commit Defender와 tenant를 선택하고 저장소 checkbox를 복수 선택한다. ‘현재 접근 가능한 모든 저장소’를 선택하면 발급 시점의 해당 tenant 저장소 ID 전체를 key에 고정한다. 기존 사용자 권한 안에서만 발급되며 이후 추가되는 저장소는 자동으로 포함하지 않는다. key 하나당 최대 100개다. 한도를 넘으면 발급을 차단하고 목록을 임의로 잘라내지 않는다. tenant 전환 시 이전 선택을 초기화한다. 기존 기간 지정·No expiration·key 폐기·원문 일회 표시와 마스킹을 보존했다.

CD의 Central Review Connection → Connect with API key…에서 GCR 화면의 HTTPS 서버 주소와 API key를 입력한 뒤 현재 작업 폴더에 연결할 저장소를 선택한다. 한 key를 허용된 여러 작업 폴더에서 사용할 수 있으나 작업 폴더마다 중앙 저장소를 하나 선택한다. 기존 로컬 Git remote 대조와 OS 자격 증명 저장소를 재사용한다. provider·model·reasoning은 GCR 연결과 별개로 유지한다.

공개 연결 JSON에는 서버 주소·저장소 ID·서명 공개키·필요한 CA가 들어 있고 key 원문은 없다. 새 CD 연결에는 필요하지 않다. GCR의 접힌 호환 항목과 CD의 Import connection JSON…에서 기존 연결 절차를 유지했다. 영문·한국어 내장 가이드도 URL·API key 절차로 바꿨다.

사설 CA를 사용하는 PRISM-DEV에서는 GCR 화면의 CA 인증서 다운로드로 공개 PEM을 받을 수 있다. CD에서 인증서 신뢰 오류가 나면 Choose CA certificate…로 해당 파일을 지정한다. 원격 CD 연결은 HTTPS를 요구하고 hostname·chain 검증을 유지한다. GCR 웹의 기존 HTTP 접속 지원은 보존한다.

## 읽기 경계

공개 `/api/v1/client-auth/config`를 검증된 HTTPS로 조회해 server ID를 얻은 뒤, Bearer key와 기존 `x-gcr-server-id` 검증을 사용하는 `/api/v1/client-auth/connection-options`를 조회한다. key에서 현재 유효한 저장소 중 기존 DB·reader·Cerbos 권한 및 enabled 상태를 통과한 저장소만 반환한다. signing public key와 공개 CA를 포함하며 credential 원문은 반환하지 않는다.

클라이언트는 응답의 server URL·server ID·tenant·client·저장소 ID·Ed25519 공개키를 검사한다. 전체 discovery는 15초, 각 응답은 최대 1 MiB이고 취소를 지원한다. redirect를 따라가지 않고 인증서를 검증하지 않은 서버에는 key를 전송하지 않는다. 사용자가 지정한 CA를 발견한 CA로 덮어쓰지 않는다. 기존 signed snapshot·만료·철회·fallback·오프라인 정책은 그대로다. 로컬 코드·diff·remote·질문·리뷰 결과는 GCR 요청에 포함하지 않는다.

CD central view 8건, client contract 22건, history 2건, central review 12건이 통과했고 타입 검사·빌드·패키징도 통과했다. 서명·repo mapping·취소·기존 JSON·local fallback 회귀를 재사용했다. 실제 모델 호출은 0회이며 모델 응답을 사용하는 회귀는 합성 executor 결과다.

실제 VS Code 1.138.0 / Electron 42.10.0 / Node 24.18.1의 별도 Extension Host에서 패키징된 CD 2.13.2를 활성화하고 명령 등록, HTTPS API key discovery와 서명된 자료의 다운로드·캐시를 확인했다. 이 연결은 시험용 HTTPS publisher와 임시 credential을 사용했으며 운영 key를 발급하거나 사용자 연결 설정을 변경하지 않았다. native URL·password 입력의 마스킹과 선택은 UI mock 테스트로 확인했고 실제 Host 검사와 구분한다. 모든 관찰된 GCR 요청은 GET·본문 0 byte였다. 시험 key와 저장소는 정리했다.

GCR의 기존 sidebar·fieldset·저장소 목록과 VS Code의 native QuickPick·InputBox를 reference로 재사용했다. 기존 user tab의 미저장 입력은 보존하고 별도 합성 화면에서 복수 선택·전체 선택·tenant 초기화와 320/420px 가로 overflow 없음을 확인했다. 캡처는 `artifacts/operations/api-key-connection-2026-09-26/clients-{desktop,420}.png`에 보관한다.

## PRISM-DEV 배포

GCR alpha.81 / chart 0.10.77을 Helm revision 89로 배포했다. release pin commit은 `d97b4185ee236eb3a3fcd17eb5af0f7bb2160d48`이다. image는 제품 source `1dceb9d`에서 생성했고 `sha256:a6034ea6e0ff7ebb182e3dd963f39e6c77ad25918e413cd80cc972cb4328ab39`로 고정했다. OCI chart digest는 `sha256:4a93b3125463b368a2f80c6deca9a3997050fb1be82ef645ced60e29335469cc`이며 공개 저장소에서 다시 받은 chart의 bytes가 원본과 같다.

strict Helm lint·render와 Linux amd64 image smoke가 통과했다. init·hook을 포함한 GCR image 참조 7개를 모두 digest로 고정했고 예상하지 않은 resource 변경은 없다. server 1/1, worker 1/1, identity 2/2가 ready이며 worker의 source sandbox도 같은 image를 사용한다. Helm test가 Succeeded로 끝난 뒤 작업용 test pod를 삭제했다.

HTTP와 인증서 검증을 켠 HTTPS에서 health·system·profile·정적 asset 응답을 확인했다. 버전은 alpha.81이며 내려받은 asset hash가 image와 일치한다. 인증 없는 profile·key·새 connection-options API는 401로 차단된다. 별도 Chrome 탭에서 기존 yjkim1 세션으로 운영 클라이언트 설정을 열어 복수·전체 저장소 2개 선택, HTTPS 서버 주소, CA 다운로드와 접힌 JSON 호환 항목을 확인했다. 브라우저 오류는 없고 운영 key를 발급하거나 폐기하지 않았다. 기존 사용자 탭의 미저장 입력은 건드리지 않았다.

기존 Secret·ConfigMap·PVC·HTTPRoute의 UID와 데이터/spec hash가 유지됐다. Helm 사용자 값은 image tag·digest 외에 동일하며 identity release revision 2와 59개 DB migration도 바뀌지 않았다. DB 연결은 `verify-full` / TLS 1.3이다.

17개 테이블의 최초 전체 hash 비교는 진행 중인 운영 분석 때문에 실패했다. 보존 검사를 임의로 성공 처리하거나 데이터를 복원하지 않고 행별 hash와 읽기 전용 실행 상태를 대조했다. 14개 테이블은 완전히 동일하고 기존 보고서 272건의 hash가 모두 남아 있으며 보고서 2건이 추가됐다. 기존 분석 280건의 hash가 같고 나머지 1건은 baseline 이후 완료된 상태다. ledger의 기존 10,134건 중 10,132건의 hash가 같고 나머지 2건은 baseline 직후 완료됐다. 최초 after snapshot에서는 ledger 230건이 늘었고 후속 조회에서는 255건이 추가된 상태였다. baseline 이전 생성 행 수가 각각 유지됐고 변화는 계속 실행 중인 운영 job과 일치한다. 이번 작업이 시작한 실제 모델 호출은 0회다. 최초 snapshot이 행별 hash만 보관했으므로 이 가변 행 3개의 변경 전 필드 값·상태까지 재현하지는 못한다.

시험용 HTTPS publisher·임시 credential·합성 화면 서버·작업용 브라우저 탭과 Extension Host용 추출 디렉터리를 정리했다. 배포 검증에 사용한 비밀값 포함 Helm values와 render 임시 파일도 삭제했다. VSIX·로그·공개 hash 근거는 보관한다. 제품·패키징·배포 변경과 이 실행 기록은 구분해 commit·push한다.
