## OS primitive 결정

Windows Credential Manager의 사용자 credential set을 사용한다.
master key와 reader key는 기존 service namespace를 구분하며 모델 API
credential은 기존 destination-bound 암호화 record와 별도 master key를
유지한다. read/write/remove는 고정 helper의 bounded stdin/stdout으로
전달한다. 평문 파일, argv, 환경변수로 secret을 전달하지 않는다.
missing과 접근 불가·손상·잠금을 구분하고 plaintext fallback은 없다.

helper는 저장소에 소스를 둔 .NET Framework 프로그램으로 빌드한다.
Windows 기본 .NET Framework 4.x와 Win32 API를 사용하며 별도 runtime
설치·관리자 실행·PowerShell 실행 정책 완화는 요구하지 않는다.
배포 artifact에 소스·Apache-2.0 license·version·hash를 포함한다.
이 machine의 ARM64 실행을 먼저 검증하고 x64는 별도 검증으로 남긴다.

데이터 기본 경로는 OS가 반환하는 사용자 LocalApplicationData 아래
CommitDefender다. 로컬 고정 NTFS volume만 허용한다. 신규 디렉터리는
생성 시점에 사용자/SYSTEM/Administrators만 허용하는 보호 DACL을
설정한다. 기존 경로의 권한을 자동 수정하지 않는다. reparse point와
비허용 SID 권한을 거절한다. 파일은 handle 검증·공유 제한을 적용하고
동일 volume의 배타적 게시를 사용한다. 파일 flush와 directory fsync의
차이는 검증 결과에 명시한다.

프로세스 수명은 kill-on-close Job Object에 실행 전에 가입시켜 관리한다.
전역 프로세스 이름별 종료는 하지 않는다. Codex 전역 지침 차단 방식은
설치된 CLI의 합성 loopback marker 검증을 통과하기 전 활성화하지 않는다.

다른 일반 사용자 접근 시험은 사용자 승인 후 임시 계정으로 수행했다.
읽기·쓰기·credential 조회가 거부됐고 계정·프로필·시험 자료를 삭제했다.
`evidence/W01-other-user.json`에 결과와 정리 상태를 기록했다.
기존 CodexSandbox 계정을 변경하거나 비밀번호를 추출하지 않는다.

전역 계정·모델·자동 실행 설정을 보존하고 사용자 창을 재로드하지 않는다.

## 실제 호출 전 고정한 fixture (2026-09-16)

새 Git 저장소의 `sum.ts`는 CRLF 파일이다. 기준 commit에서는
`total + value`, staged 변경에서는 `total - value`를 사용한다.
`consumer.ts`의 invoiceTotal이 sum을 호출하고,
`sum.test.ts`는 [2, 3] → 5와 빈 배열 → 0을 검증한다.
호출 전에 첫 검사가 -5로 실패하고 빈 배열 검사가 통과해야 한다.
`.env`의 합성 canary는 모델 입력과 결과에서 제외돼야 한다.

기대 결과: sum.ts의 뺄셈 때문에 양수 합계가 음수가 되는 결함을
source/base 및 caller/test를 근거로 지적한 completed 리뷰를 얻는다.
동일 runId를 암호화 이력에서 다시 열어 결과가 같은지 확인하고
설치된 확장의 저장 결과 열기 명령을 실행한다. 검증용 프로필에서만
자동 실행을 끄고 fixture 경로만 신뢰한다. 전역 사용자 설정과
VS Code/Electron sandbox 설정을 변경하지 않는다.

실제 호출 한도는 여전히 1회/240초다. 합성 catalog probe는 실제
계정 호출 0회이며, provider가 의도적으로 종료한 code 1을 리뷰
성공으로 해석하지 않는다. 허용 tool catalog와 지침 canary 부재만
검증한다.

## 구현과 검증된 범위

공통 client alpha.47, native helper 1.0.1을 VSIX 2.12.2에 포함했다.
helper의 .NET Framework AnyCPU 실행은 이 Windows ARM64 machine에서
검증했다. 빌드는 .NET SDK 8 Roslyn의 결정적 빌드이며 배포 시 SDK를
요구하지 않는다. 소스·Apache-2.0 license·실행 파일 hash를 함께 보관한다.
공통 패키지는 clean consumer에서 설치·import·native identity를 검증했다.

기존 Codex auth.json에 대한 NTFS hard link만 per-process CODEX_HOME에
노출한다. 원래 계정 파일을 읽어 복사하거나 전역 CODEX_HOME/config를
바꾸지 않는다. 전역 AGENTS.md/override/Skills/config canary가 실제
CLI의 합성 요청에 없는지 확인하고, 고정 source 도구 allowlist를 실제
요청에서 비교한다. 실제 리뷰와 이 합성 검사의 성공 의미를 구분한다.
Windows의 범용 OS sandbox를 새로 제공하는 구현은 아니다. 기존
read-only 모드와 명령·파일 시스템·웹·추가 provider 도구 차단을 유지한다.

파일 생성은 protected DACL, handle 기반 reparse 거부, 열린 조상 경로의
삭제 공유 제한, 파일 flush와 같은 volume의 배타적 MoveFileEx 게시를
사용한다. 6개 동시 게시 중 하나만 성공했고 CAS 충돌·손상·중단된
게시를 구분했다. 게시 helper를 실제 종료해도 대상 파일이 없거나
완전한 내용만 보였다. Windows directory fsync는 구현하지 않았으며
전원 손실 시 directory metadata의 POSIX 동등 내구성은 주장하지 않는다.

프로세스는 shell 없이 .exe와 literal argv로 실행한다. helper가 자식
생성 전에 kill-on-close Job Object에 들어간다. timeout/취소/leader 종료/
소유 Node 종료 때 후손을 정리하고 독립 프로세스는 보존한다. 출력 EOF와
정리가 확인되지 않으면 성공으로 반환하지 않는다. .cmd/.bat wrapper는
거절하며 CLI 설치나 PATH를 전역 수정하지 않는다.

검증: alpha.46의 GCR W01 집중 회귀 47 통과, 0 실패, 플랫폼 전용 8 제외.
후속 Electron read-only 정리 수정은 실제 VS Code의 Node 24.18.1에서
한국어·공백 경로 worker 회귀 1건으로 검증했다. CD 명세 22건,
설정 4건, 수동 리뷰 회귀 6건, build와 test typecheck가 통과했다.
다른 사용자 시험은 승인된 임시 표준 계정의 실제 logon으로 수행했고
private 파일 읽기·쓰기 및 credential 조회가 거부됐다. 계정·프로필과
credential·시험 자료 삭제를 확인했다. OS 보안 primitive 검증 후 변경은
긴 경로 지원·프로세스 정리·JS worker/임시 파일 정리이며 DACL과
Credential Manager의 사용자 분리 규칙은 유지했다.

초기 광범위 검사(215 통과/164 실패/8 제외)는 빌드와 실행이 겹친
영향 및 POSIX 전용 fixture를 포함해 통과 근거로 쓰지 않는다.
CD 전체 suite도 W01 성공 근거로 사용하지 않았다. 필요한 수동 경로를
별도로 실행했다. macOS/Linux 네이티브 회귀 환경과 기존 원격 CI workflow는
없어 실행하지 않았다. 해당 OS 분기는 유지했지만 새 native 성공을
주장하지 않는다.

## 수동 사용과 정리

사용자가 편한 시점에 확장을 다시 활성화한 뒤 Extensions에서 2.12.2가
적용됐는지 확인한다. 기존 Codex 계정과 명시적으로 선택한 provider/model
설정을 유지한다. 중앙 연결 없는 실행 모드는 `standalone`이다.
신뢰한 Git workspace에서 Command Palette의
`Commit Defender: Analyze Staged Files` 또는
`Commit Defender: Analyze Current File`을 실행하고 History 항목을 열어
저장 결과를 조회한다. 자동 실행 설정이나 service는 이 작업에서 켜지 않았다.

실제 모델 수용 검사는 staged 경로 1회다. current-file은 기존 공통
snapshot/worker 경로를 유지했으며 별도 실제 모델 호출은 하지 않았다.
실패 시 표시된 상태를 확인하고 준비·권한·모델 오류를 성공 결과로
취급하지 않는다. 취소는 `Commit Defender: Cancel Analysis`를 사용한다.

[보존 확인](evidence/W01-preservation.json)에서 VS Code settings.json,
Codex config.toml/AGENTS.md의 시작/종료 hash가 같음을 확인했다.
기존 ChatGPT 로그인은 유지됐고 auth.json hard link 수는 다시 1이다.
Codex CLI도 0.153.4 그대로다.

검증용 계정·프로필·native helper 프로세스도 남지 않았다. 실제 Host의

기존 사용자 계정, Codex Sandbox 계정과 다른 실행은 보존했다.

## 전달 범위와 제한

로컬 고정 NTFS, 파일 기반 기존 Codex 계정, 검증된 Codex CLI 0.153.4,
Windows 11 ARM64/VS Code 1.137 조합이 이번 범위다. x64, WSL,
Remote SSH, Dev Container, UNC/network/FAT 및 keyring-only Codex 계정은
검증된 지원으로 표시하지 않는다. source index 읽기는 Windows에서
24 MiB로 제한한다. NTFS hard link이므로 원래 auth.json과 실행 임시
디렉터리가 같은 volume이어야 한다. 관리자 권한은 제품 실행에 필요 없다.

보안 helper 시작 비용 때문에 저장 연산이 느리다. 이 machine에서
identity helper 5회 평균은 약 362 ms였고, CD 합성 수동 회귀 6건은
약 132초였다. 성능·x64·자동 리뷰·중앙 자료 전체 검증은 W01 완료 주장에
포함하지 않는다. W02–W04, P11, PRISM-DEV, 중앙 업로드, Marketplace는
시작하지 않았다.
