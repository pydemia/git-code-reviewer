# W04 — 최종 수용 검토와 플랫폼 회귀

상태: **미완료**. Windows ARM64 검증에 이어 [macOS 필수 회귀](W04-macos.md)를 완료해 W-A09를 충족했다. W-A10의 Windows 삭제 차단 폴더 19개 수동 정리는 별도로 남아 있다. 아래 기존 실행·실패 기록은 보존하며 macOS 추가 결과는 연결 문서에서 구분한다.

이후 사용자가 macOS 회귀를 다른 장비에서 수행하기로 했다.
[다른 장비 인계 지시서](W04-macos-handoff.md)와
[/goal 명령](W04-macos-goal.md)에 검사 범위·고정 artifact·판정 조건을 기록했다.
인계 문서 작성은 macOS 실행 또는 Windows 수동 정리 완료를 뜻하지 않는다.

## 테스트 변경과 실행 결과

W03의 Windows 15/23 결과는 POSIX shebang 파일을 native executable로 실행하는
fixture 가정 때문에 발생했다. Linux의 기존 fake Codex 경로는 유지했다.
Windows에서는 native Node 자식 process가 loopback HTTP로 합성 응답을 제공하고
기존 OpenAI adapter가 같은 failed/partial/cancel/timeout 판정 검사를 수행한다.
skip이나 성공 조건 완화는 없다. legacy Python hook 기능은 확장하지 않았다.

실제 `out/hook-cli.js`를 실행하는 두 검사는 기존 W03 bundle을 사용한다.
시험용 key는 고유 profile의 Windows 보안 저장소에 저장하고 hook JSON에는
credential 참조만 쓴다. provider 도달 1회, FAILED/PARTIAL 표시와 PASS 부재,
기존 허용·차단 exit code를 확인한다. 종료 시 key 삭제·재조회 부재와 fixture
자식의 exit 0을 assert한다. 실제 모델이나 운영 credential을 사용하지 않는다.

중간 실패도 [검증 기록](evidence/W04-validation.json)에 보존했다. 최초 Windows
재실행은 21/23이었다. hook의 평문 key 설정을 제품이 정상적으로 거부한 원인을
확인하고 fixture를 보안 저장 참조로 수정했다. 보안 검사를 해제하지 않았다.

| 실행 환경 | 검사 | 실제 결과 |
| --- | --- | --- |
| Windows 11 ARM64, Node 24.16.0 | CD test typecheck | 통과 |
| Windows native | review-outcome, API hook 실행 포함 | 23/23, 실패·skip·cancel 0 |
| Windows native, helper 1.0.3 | NTFS/원자성/snapshot 6, IPC 1, process 6, 격리 3 | 16/16 |
| Linux ARM64 container, Node 22.23.2 | 최종 review-outcome bundle | 23/23, 실패·skip·cancel 0 |
| Windows native | 기존 고정 package의 offline clean consumer | 4개 import/CLI/helper 대조 통과 |
| macOS native | 영향받은 공통 저장·실행·service 회귀 | [후속 macOS 회귀 완료](W04-macos.md); 원래 Windows 실행에서는 미실행 |

Linux는 기존 `pydemia/git-code-reviewer:0.8.0-alpha.3` 이미지에서 network none,
readonly 소스 mount로 실행했다. WSL이나 Windows native 증거가 아니다.
합성 executor는 상태·경계 동작만 검증하며 모델의 판단 품질 증거로 쓰지 않는다.

## 실제 모델 결과의 범위

W04 추가 모델 호출은 0회다. 기존 기본 Codex 계정과 `gpt-5.6-luna / high`의
W01 수동 리뷰, W02 중앙 문맥 리뷰, W03 service 리뷰를 재사용했다. runtime
hash가 같으며 문서·test 변경으로 제품 리뷰를 반복하지 않았다.

W02는 사용자 승인으로 실제
[pydemia/commit-defender PR #3](https://github.com/pydemia/commit-defender/pull/3)의
원문·답글·본문 버전과 로컬 GCR 활성 지침을 대조한 결과다. 원래 PRISM 자료를
검증하지 않았다. 기존 PR·branch·댓글·답글은 수정하지 않았다. 시험 서버·DB·
credential은 정리된 상태이며 새로운 중앙 통신이나 외부 게시를 하지 않았다.

W03 모델 호출은 2회, 내용·근거·저장 재조회를 확인한 완료 report는 1건이다.
[첫 호출](evidence/W03-native-host-attempt1.json)은 결함 발견 exitCode 1을
harness가 실행 실패로 판단하여 report 본문을 확인하지 못했다. 성공 제외다.
[두 번째](evidence/W03-native-host-attempt2.json)는 `report.status=completed`,
problems 0, 검증된 결함 1개와 암호화 저장 재조회를 확인했지만 outer Host
launcher가 cleanup-failed를 반환했다. 전체 launcher 성공으로 표시하지 않는다.
[별도 수명 검사](evidence/W03-native-host-lifecycle.json)는 모델 호출 없이
service를 먼저 정상 종료한 뒤 Host를 닫아 통과한 결과다.

exitCode, service completed나 reviewCompletionConfirmed만으로 모델 성공을
판정하지 않는다. unknown-read-id, partial, timeout, 실패는 완료 건수에 넣지
않는다. source를 읽었다는 관찰은 테스트 실행이 아니다.

## 정리와 남은 작업

[보존 검사](evidence/W04-preservation.json)에서 설정·CLI·기존 hook을 대조했다.
W04 시험 credential은 삭제 후 부재를 assert했으며 새 OS 계정은 만들지 않았다.
새 consumer·fixture·profile·session·service와 관찰된 시험 process는 남지 않았다.
사용자 Host·계정·다른 service/container를 종료하거나 설정을 바꾸지 않았다.

W03의 자동 승인 검토가 `blocked by policy`로 거절한 재귀 삭제 19개 경로는
아직 존재한다. 상세 거절 사유는 제공되지 않았다. 삭제를 재시도하거나 다른
도구로 우회하지 않고 [정확한 수동 정리 목록](W04-cleanup.md)을 남겼다.

후속 [macOS 회귀](W04-macos.md)에서 최종 package의 Keychain 저장·재시작·손상 처리, snapshot,
Unix service 소유·복구·종료, process 취소/timeout, Codex catalog/marker 격리와
managed hook/outcome 회귀를 실행했다. 기본 모델 추가 호출은 계속 0회다.
실제 모델 재검증이 필요해질 때만 변경 영향과 호출 한도를 먼저 기록한다.
실행하지 않은 macOS 검사를 성공으로 바꾸거나 새 CI를 만들지 않는다.

완료 판단은 [W04 감사](evidence/W04-completion-audit.json), 전달 commit은
[전달 기록](evidence/W04-delivery.json)에 연결한다.
