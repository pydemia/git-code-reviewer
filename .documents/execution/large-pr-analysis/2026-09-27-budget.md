# 대형 PR 모델 호출 한도 증액 — 2026-09-27

사용자가 GCR의 모델 호출 횟수 한도 증액을 요청했다. 실제 PRISM-DEV
ConfigMap, Helm values와 worker 환경에서 대형 분석 한도 **256회**를 확인하고
**512회**로 늘렸다. 일반 분석 기본값 128회, 대형 분석 3시간 제한, 대화 한도,
계정 공통 admission과 provider의 rate limit·사용량 제한은 유지한다.

## 변경 및 적용

- 저장된 배포 설정: `deploy/environments/prism-dev/values.yaml`의
  `model.analysis.groupMaxModelCalls` 한 값만 256에서 512로 변경했다.
  설정 commit은 `c497376`이다.
- 기존 Helm release의 values를 재사용하고 해당 값만 override했다.
  Chart `0.10.79`, app `0.8.0-alpha.83`, image digest
  `sha256:a6a8de1bbfc1317749be0e2367a05bdad8e08e8e954c86b98f66770a19988a43`
  는 바꾸지 않았다. 이미지나 공통 package를 다시 빌드하지 않았다.
- Helm revision 91 → **92**, 상태 `deployed`. 현재 chart에서는 이 변경으로
  server의 config checksum만 갱신된다. worker는 시작 당시 환경값 256회를
  유지하는 것을 확인해 rolling restart를 명시적으로 실행했다. 기존 Pod의
  종료를 기다렸으며 강제 삭제나 grace period 축소는 하지 않았다.
- 재시작 후 실제 server·worker 프로세스 환경에서 모두 **512회**를 확인했다.
  worker의 3시간 제한은 10,800,000ms이고 일반 분석 변수는 기존처럼 설정되지
  않아 runtime 기본값 128회를 사용한다.

## 검증과 보존

Helm lint를 통과했다. 서버 dry-run에서 Kubernetes resource 변경은 호출 한도
ConfigMap 필드와 server config checksum뿐이었고, 전체 Helm values를 대조해
`model.analysis.groupMaxModelCalls` 이외의 값이 같음을 확인했다.

배포 후 Secret·ConfigMap·PVC 21개의 UID와 데이터/spec을 대조했다. GCR
ConfigMap의 호출 한도 필드 이외의 기존 리소스 내용은 같다. 이미지, replicas,
계정 공통 admission 활성화, worker concurrency 2, identity deployment를
보존했다. Server·worker는 각각 Ready 1/1, identity는 Ready 2/2이며 deployment
generation과 observedGeneration이 일치한다. DB 데이터나 사용자·모델·계정
설정은 직접 수정하지 않았다.

이 작업에서 LLM 시험 호출, 분석 재개/신규 분석 요청, GitHub 댓글 게시 요청은
수행하지 않았다. 과거 comment와 완료/미완료 결과는 보존한다. 한도 증액만으로
예전 comment가 갱신되거나 중단된 분석이 자동으로 새 revision으로 재개되는
것은 아니다. 이후 대형 그룹 분석 또는 해당 분석의 명시적인 재개가 새 worker
설정을 사용한다.
